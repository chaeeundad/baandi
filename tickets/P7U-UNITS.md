TASK_ID: P7U-UNITS
GOAL: Replace the hand-written conversion constants in dft-units by a general-purpose units library (uom, already added to the workspace manifest and vendored by Claude: license Apache-2.0 OR MIT) and support all common units at the input and output boundaries: energy Ha, Ry, eV (also meV and J), length Bohr, Angstrom (also nm, pm, m), pressure for later stress work (Ha/Bohr^3, Ry/Bohr^3, eV/Angstrom^3, GPa, kbar, Pa). Internally the engine stays in Hartree atomic units (Bohr, Hartree); conversions happen only at the boundaries. No conversion factor or CODATA number may be typed in the workspace outside tests; derive everything from uom quantities. Ry = Ha/2 is a definition (ADR 0003 exception, state it), not a measured constant.
OWNED_FILES: crates/dft-units/** (code and tests), crates/dft-cli/** (unit-aware input parsing, a `convert` subcommand, extra output fields; keep every existing option, TOML field and output field working), docs/decisions/0012-units-library.md (create), docs/cli.md (append or adjust unit sections), docs/physics-conventions.md (append a short units section only), docs/dependencies.md (add uom: version from Cargo.lock, license, consumer dft-units, note which uom features are on, transitive crates num-traits and typenum plus autocfg build dep), scripts/tests/test_no_hardcoded_units.py (create). Do not touch the workspace Cargo.toml or Cargo.lock (already updated), other crates, other ADRs, AGENTS.md, ownership.toml, tickets/, artifacts/. If another crate calls an API you must change, keep the old API working (deprecate, do not break) because other tickets are in flight.
READ_ONLY_CONTEXT: AGENTS.md, ownership.toml, crates/dft-units, crates/dft-cli AGENTS.md and sources, docs/cli.md, docs/physics-conventions.md, docs/decisions/0003, 0005, and the uom 0.38 source in the vendored directory (look for how hartree, bohr_radius, electronvolt, pressure units are defined; note rydberg is not defined in uom).
DESIGN REQUIREMENTS (record in ADR 0012):
1. dft-units public API: keep the existing newtypes (Bohr, Angstrom, Hartree, Rydberg, ElectronVolt) and their From conversions working, but compute the factors from uom (the CODATA 2018 values used by uom must reproduce the values the MVP validated: Bohr in Angstrom 0.529177210903 and Hartree in eV 27.211386245988 to within their last printed digit; add a test that states and checks this so that the validated SCF numbers do not silently change). Add enums `EnergyUnit`, `LengthUnit`, `PressureUnit` and value types or functions `convert_energy(value, from, to)`, `convert_length`, `convert_pressure`, plus `to_hartree`/`from_hartree`, `to_bohr`/`from_bohr`. A strict parser for strings like "30 Ry", "30Ry", "408.2 eV", "5.43 Angstrom" (case-insensitive unit names and a documented closed list of aliases such as ha/hartree, ry/rydberg, ev/electronvolt, bohr/a0, angstrom/ang/A, nm, pm; units are NOT guessed: unknown unit, missing unit when one is required, NaN, inf, empty string and extra tokens are typed errors with the offending text).
2. Precision: conversion through uom (f64). Document the round-trip error bound and test round trips for every unit pair (relative 1e-14).
3. dft-cli: wherever the TOML currently takes a cutoff or lattice or tolerances with unit-suffixed field names (see docs/cli.md), additionally accept a unit string through a documented alternative (for example `cutoff = "30 Ry"`, `lattice_constant = "5.43 Angstrom"`; choose a design that keeps old inputs valid, reject specifying both a legacy field and its unit-string form, and make the resolution rules explicit in docs/cli.md). Add `dft-cli convert <value> <from> <to>` printing the converted value with 15 significant digits and exit codes consistent with the existing CLI (usage error code as documented). results.json: keep existing fields and add, for the total energy, an additive block with the value in ha, ry, ev (all derived from the same Hartree value through dft-units); mention it in docs/cli.md and keep the report schema docs consistent.
4. Hardcode guard: scripts/tests/test_no_hardcoded_units.py (python3 -I, standard library only) scans all .rs files outside crates/dft-units for the digit prefixes of the conversion constants (0.5291772, 27.21138, 13.60569, 1.602176, 4.359744, 2.941e4 style pressures) and fails with file and line if found; allow a documented allowlist for test reference files under tests/ and for comments in docs. Also scan crates/dft-units/src (non-test code) so that only uom provides the numbers. Verify the guard fails when a literal is planted (test the guard on a temp copy, not by editing the repo).
TESTS: unit tests with stated tolerances and printed values: (a) 1 Ha = 2 Ry exactly; (b) Ha to eV equals the CODATA 2018 value 27.211386245988 to the printed digits; (c) Bohr to Angstrom equals 0.529177210903; (d) 30 Ry equals 15 Ha; 13.605693122994 eV per Ry within last digit; (e) pressure: 1 Ha/Bohr^3 in GPa compared against an independent computation from the SI values of Hartree energy in J and Bohr in m written out as published CODATA 2018 numbers in the test (state the source), tolerance 1e-9 relative; 1 GPa = 10 kbar; (f) parser accepts and rejects the cases above; (g) all unit pair round trips; (h) CLI integration tests: `convert 30 Ry Ha` gives 15, a TOML with `cutoff = "30 Ry"` yields the same SCF input as the legacy field, both given is rejected, unknown unit rejected, results.json gains the energy block and old fields unchanged; (i) the engine regression: the existing fast tests still give the same numbers; scripts/check.sh green; python3 -I -m unittest discover -s scripts/tests green.
ACCEPTANCE_CRITERIA: no hand-typed conversion constant left in non-test workspace code (the guard proves it); validated SCF numbers unchanged; legacy inputs still work; no tolerance loosened; ADR 0012 and docs updated; no new dependencies beyond uom.
NON_GOALS: dimensional-analysis types throughout the engine (the engine keeps f64 in atomic units; typed quantities only at the boundary), temperature units, magnetic units, changes to numerical code.
