# Preconditioned ionic relaxation: user specification (2026-11-27)

Verbatim task specification from the user, recorded for agents. Summary of the binding points:

- Objective: reduce DFT energy/force evaluations and end-to-end wall time of ionic relaxation with physics-based preconditioning (preconditioned L-BFGS and related), keeping accuracy, physical validity, robustness and scalability. The algorithm is not the objective.
- Evidence so far (ASE EMT, median evaluations): Cu(111)+CH3OH BFGS 172 / LBFGS 158.5 / PreconLBFGS(Exp) 88 / A3 69; Ni(111)+C2H4 185.5 / 184 / 99 / 99.5; Au/Cu alloy 21 / 21 / 12 / 13. Does not establish a DFT benefit.
- Literature: Packwood et al. JCP 144, 164109 (2016); exponential and sparse graph-Laplacian preconditioners; bond/element-aware metrics; preconditioned L-BFGS; model Hessians and internal-coordinate preconditioning; line search and trust region. ASE PreconLBFGS as a reference, not mandatory architecture; check licenses before reuse.
- Phase 0 audit (BFGS, FIRE, force/SCF paths, warm starts, Hessian init/update, step control, convergence criteria, fixed atoms, PBC, restart/checkpoint, bottlenecks; SCF noise). Preserve the current behaviour as a baseline.
- Phase 1 DFT validation through the BAANDI ASE calculator: BAANDI BFGS, BAANDI FIRE, ASE BFGS, ASE LBFGS, ASE PreconLBFGS(Exp), experimental A3 + L-BFGS; systems Si8-AlP, 63-atom Si-Al-P vacancy, perturbed bulk Si, defects, surfaces/adsorbates (TiO2 + molecules) when stable; inexpensive systems first; multiple perturbations and seeds; use existing inputs and settings.
- Fairness: identical structure, PPs, XC, cutoff, k points, SCF tolerance, occupations/smearing, constraints, ionic criteria, hardware and parallel configuration; never mix warm and cold starts in wall comparisons; count every attempted evaluation (rejected line-search steps, failed SCF); common external convergence evaluator; primary target max atomic force NORM 0.02 eV/A (3.89e-4 Ha/Bohr) plus intermediate thresholds; never substitute max Cartesian component.
- Phase 2 (only with evidence): native Rust preconditioned optimizer integrated with the relaxation architecture; warm starts preserved; no mandatory Python/ASE; constraints/PBC; large systems; restart/checkpoint; low overhead; sparse physically motivated P (e.g. P = mu(L + eps I), SPD on the active subspace, sparse solves, fragments/surfaces/vacuum/adsorbates handled; L-BFGS history consistent with preconditioner updates).
- Robustness: descent checks, SPD safeguards, regularization, max displacement, line search/trust region, curvature checks, SCF-failure recovery, rejected steps, fallback direction; convergence only on real BAANDI forces; report different minima explicitly.
- Metrics per run: attempted evaluations, SCF success/fail, accepted/rejected steps, total SCF iterations, wall, evaluation time, preconditioner construction/application time, line-search overhead, peak memory, final energy, final max atomic force norm, final structure, status; early/intermediate/late stage analysis; paired comparisons, medians, distributions, failures.
- Targets: evaluations -20% (prefer -40..50%), wall -20% (prefer -40..50%), preconditioner overhead <5% (prefer <1%), no reliability degradation, equivalent accuracy; compare against competitive preconditioned optimizers, later QE under equivalent conditions.
- Interface: existing relaxation configuration, minimal surface, sensible defaults; no new env variables or excessive switches; backward compatible; not the default until established.
- Tests: SPD, inverse accuracy, invariances, PBC, fixed atoms, disconnected fragments, weak adsorbates, large condition numbers, sparse scalability, L-BFGS history, SCF failure recovery, restart consistency, reference structures, BFGS/FIRE regression.
- Deliverables: audit, design, DFT benchmarks, native implementation if justified, tests, reproducible scripts and raw results, performance/scalability analysis, user documentation, default recommendation.
- Acceptance: reproducible end-to-end improvement without loss of correctness or reliability; otherwise document and do not add complexity.
