# Brief for the planning agent: architecture change proposal for the si64 MPI8 gap (orchestrator, 2026-11-23; user approved direction 2 "structural redesign")

## Question
Local optimizations of the existing lanes do not move the si64 MPI8 gap (BAANDI 10.76 s vs QE 4.64 s, A-D = 6.12 s, A/R 2.36; si32 np8 A/R 2.125). Propose a structural design change that can plausibly remove most of the gap, with pre-registered gates, staged so that each stage is measurable on dev08 and reversible. Same parallel model on both sides only (one core vs one core, MPI vs MPI); GPU, threads (OpenMP) lane and the verification judgment rule are out of scope or unchanged. Accuracy gates stay: strict 1e-10 Ha / standard 5e-9 Ha, certificate (fixed-point verification) stays on.

## Measured facts (dev08, relayed; files: docs/performance/requests/si64-gap-attribution-2026-11-20.md, docs/performance/attempts-ledger.md, docs/performance/lanes/*)
1. Gap decomposition, si64 np8 at 279278d (instrumented proportions, seconds, BAANDI - QE Davidson): subspace algebra +1.91 (reduced_gram 1.00, reduced_eigen 0.99 over 183 calls, rotate 0.96, kept_update 0.57), H application +0.87 (BAANDI apply 2.78 vs QE h_psi 1.91; nonlocal 26 %, FFT + local 74 %), solve work outside the solver envelope +0.77, outside process (launch/exit) +0.72, start (atomic_start) +0.41, density +0.41, energy+potential+mixing +0.35, io/materialize +0.30, other init + between +0.39. BAANDI iterations: coarse 32, fine 58, verify 11; QE's ethr starts at 1e-2 and tightens adaptively (first four SCF steps only 1-3 iterations).
2. RMM (QE's best) is worth only D-R = 1.4 % of the gap (si32 1.3 %, unresolved): not a lever.
3. Scale dependence (si32 -> si64, same commit): gap per responsibility grows H application 5.61x (BAANDI apply 4.18x vs QE h_psi 3.75x), density 4.91x, subspace algebra 4.75x (QE 5.03x), start 4.33x, potential 3.03x; arrival skew median 9.74x vs wall 4.47x; per-rank collective wait 2.4 % -> 3.4 % of wall. Fixtures stop at 64 atoms; si128/si216 fixtures are being added.
4. Closed levers (ledger rows): changing MKL GEMM call shapes (UPPER_BORDER +0.57 % loss, ROTATE_COLUMNS +6.1/+4.2 % loss: the existing 256-row panel is optimal, 108 GFLOP/s vs 54); reducing collective volume (PACKED_REDUCE -28 % payload, no wall change; FFT all-to-all and reduce are WAIT not volume); kept_copy/multiply fusion (neutral); nonlocal fusion (<= 0.05 s); coarse fraction/stop rules (126 arms, no general rule); owned handoff, minimum grid, verification first-attempt predictor (not proven at si64).
5. What worked: removing intermediate-array memory traffic (serial density fusion, -3.7..-4.8 % at one core) and fixed costs (binary hash cache 0.1 s), atomic start local block (-1..-2 % one core). None helps the MPI8 gap.
6. Parallel facts: pure MPI, ranks bound to physical cores 0-7 of socket 0 (np16: cores 0-15), stick-row distributed FFT (M2), real-Gamma pairing (0.69 forward + 0.71 inverse FFT pairs per H column), 6025 H columns per run at si64 (coarse 1753 / fine 3504 / verify 768); permutation passes run at 6-7 GB/s under MPI vs 13-14 GB/s serial (socket bandwidth shared); FFT axes 15-16 GFLOP/s (about 2 ns per point); arrival skew is rank-late-leaving of specific compute stages (solver.append, FFT permutation, projector gemm), ownership counts are balanced (max 2 sticks / 4 rows difference).
7. Open: regression check d6be1d0 vs 279278d (si32 np8 B 2.20 s vs A 2.72 s at equal QE time) queued on dev08.

## What to deliver
(1) A candidate architecture (or two alternatives) with the mechanism that removes time: for example owned grid/orbital state kept across the whole SCF map (no replicated glue, no materialization), fusion of the H-apply pipeline (FFT, local potential, nonlocal) to cut memory passes, a different subspace/eigensolver organization with fewer, larger operations, adaptive tolerance schedule like QE's ethr, treating coarse+verification (2.5 s with no QE counterpart) differently, using the one-core-proven trick (removing intermediate array traffic) in the MPI path. Quantify each expected gain from the measured table above (seconds, with the arithmetic or bandwidth floor), and state which part of the 6.12 s it can remove at most.
(2) A staged plan: each stage small enough for one Codex ticket, with a pre-registered dev08 counter that must move and a wall gate (|mean|/SE >= 3 crossed pairs, A/A floor first), same-model comparison only, plus the generality set (si16, si32, si64, si128 np8; si32/si64 one core; skewed and slab cells; synthetic PPs) and the accuracy gates; define stop/rollback rules.
(3) The honest probability and the cost estimate; what must be measured first to choose between alternatives (list cheap dev08 measurements).
(4) Points where the design needs a user decision (scope, contracts).

## ADDENDUM 2026-11-23 (late): SCF map count grows with size, a convergence problem hidden inside the ratios
First valid larger-cell data (dev08, single provisional runs, np8, BAANDI vs QE david): si128 (2x2x4 cells, 128 atoms, 260 bands) BAANDI 79.27 s, SCF (fine maps) 29, H applications 14,859, maxRSS 1.90 GB; QE 23.1-24.0 s, RSS 191 MB; ratio 3.42. si216 (3x3x3, 436 bands) BAANDI 227.51 s, SCF 21, H 18,579, RSS 5.07 GB; QE david 85.37 s, 14 SCF steps; ratio 2.67 (energy agrees to 5.5e-4 Ry). Per SCF step at si216: BAANDI 10.83 s vs QE 6.10 s = 1.78x, so about 1.5x of the 2.67x is the NUMBER OF SCF MAPS (21 vs 14), not per-step cost. At si64 BAANDI fine maps = 11 and QE 12; at si128 BAANDI needs 29. The elongated 2x2x4 cell needs far more maps (charge-sloshing-type slow mixing along the long axis is the first suspect). The earlier statement "mixing is already equal to QE" referred to per-map mixing TIME, not to the number of maps. Memory: BAANDI/QE = 9.9x (si128), 13.4x (si216). NUMA/THP does not explain the 20 % window-to-window variation (A/B/C within a window 1.0-1.3 %, membind -1.7 % unresolved). Consequences for the redesign: (1) the number of SCF maps and the mixer/preconditioner (issues #21 response-based preconditioning, mixing survey, MIX_COULOMB_GUARD parked) may be a larger lever than any per-map cost at larger cells; (2) per-step and per-map decompositions must be separated everywhere; (3) memory scaling (9.9x/13.4x) matters for the 10k-atom goal.
