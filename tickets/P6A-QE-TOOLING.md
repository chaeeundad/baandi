1. scripts/make_qe_input.py: `make_qe_input.py --results RESULTS.json --pseudo-dir DIR --upf-name NAME --out qe.in [options]`. It reads our results.json (cell lattice in Bohr as columns, atoms fractional, cutoff in Ry, electrons, bands, grid, scf options) and writes a pw.x input that reproduces our conditions: ibrav = 0; CELL_PARAMETERS in bohr with the three lattice vectors as ROWS (convert from our columns, document), numbers printed with 17 significant digits so geometry is bit-identical in Bohr (this removes any Angstrom-Bohr constant ambiguity); ATOMIC_POSITIONS crystal; ATOMIC_SPECIES with mass 1.0 placeholder and the UPF name; K_POINTS automatic 1 1 1 0 0 0 (the complex Gamma path, NOT the `gamma` real-wavefunction trick; explain why in comments); ecutwfc from our cutoff in Ry, ecutrho = 4*ecutwfc; nbnd = our number of bands; occupations = 'fixed'; nosym = .true.; noinv = .true.; diagonalization = 'david'; diago_full_acc = .true.; conv_thr small (default 1e-12 Ry, option); mixing_beta option (default 0.7); electron_maxstep 200; disk_io = 'low'; verbosity = 'high'; tprnfor/tstress false; `input_dft` NOT set (the UPF's own functional must be used, and the verifier will check what pw.x reports). Options: `--fft-grid ours` writes nr1, nr2, nr3 equal to our grid, `--fft-grid auto` leaves QE's default (default value of the option: both variants must be producible; the scan emits both); `--ecut-ry` override; `--prefix`, `--outdir` text. Output also a sidecar `qe.in.meta.json` with sha256 of the generated input, the source results.json sha256, the UPF name and our UPF sha256 from results.json, and the exact generator options. Tests: generated text for a synthetic results.json equals an expected string (golden, written by you from the documented format), rows-vs-columns conversion test with a non-symmetric lattice, bit-exact round trip of the printed lattice numbers (parse back and compare floats exactly), both FFT variants.

3. scripts/verify_qe.py: `verify_qe.py --ours OUT_DIR_or_results.json --bundle BUNDLE_DIR [--tol-... options] [--json report.json] [--markdown report.md]`. Strict parser for pw.x output of a single-k-point scf run with verbosity high: program version line; number of electrons; number of Kohn-Sham states; kinetic-energy and charge-density cutoffs; FFT dimensions; number of plane waves (from the k-point line "(  N PWs)" or equivalent, state exactly which pattern you require); the exchange-correlation line; the final total energy line starting with "!"; the energy decomposition lines (one-electron contribution, hartree contribution, xc contribution, ewald contribution); eigenvalues of the single k point in eV; highest occupied and lowest unoccupied levels if printed; "convergence has been achieved in N iterations"; total wall time line if present. If any required item is absent the parser raises with the missing pattern; no defaults. Conversions: 1 Ha = 2 Ry exactly; eigenvalues from eV to Ha using the CODATA 2018 value 1 Ha = 27.211386245988 eV and note that QE's own constant may differ in the last digits (state the sensitivity: eigenvalue differences at the 1e-9 relative level are irrelevant to the tolerances). Condition checks BEFORE comparing numbers (exit 3 on failure, listing each failed condition): same cutoffs (Ry), same number of electrons, same number of bands, same FFT dimensions (if the bundle's input requested our grid; if QE used its own grid, record both grids and continue with a warning flag in the report), same plane-wave count, same lattice and positions within 1e-12 Bohr (compare qe.in numbers with our results.json), QE's reported functional string consistent with LDA-PZ (print what QE printed). Then comparisons, each with an absolute difference, unit, tolerance and PASS/FAIL: total energy per atom (default tolerance 1e-4 Ha/atom), each decomposition term (reported, with default tolerance 1e-4 Ha, flagged informational if QE's decomposition conventions differ: document the mapping one-electron = kinetic + local + nonlocal, hartree, xc, ewald from docs/physics-conventions.md and results.json), eigenvalues (default 1e-3 Ha, all bands), HOMO-LUMO gap, electron count (relative 1e-8). Report the maximum differences and which item attains them. Do NOT relax any tolerance silently; options exist but the report must print the tolerances used and flag any value that differs from the defaults. Output a markdown report and a JSON report; the report must state the provenance fields and the UPF provenance note "unverified" read from our docs (hard-code the sentence "Pseudopotential provenance is unverified" into the report header when the UPF sha256 equals e8d933754cd51c6bb4b2a809151f89e0647e53d878bab88d26e1b5a5d68d5217).
4. scripts/convergence_scan.py: `convergence_scan.py --input INPUT.toml --dft-cli PATH --out-dir DIR --scan {ecut,grid,tolerance,all} [--ecuts 20,25,30,40,50,60,80] [--grids ...] [--emit-qe-inputs --pseudo-dir DIR --upf-name NAME]`. For each scan point it writes a TOML derived from the input (copy with changed [basis] ecutwfc_ry or fft_grid or [scf] tolerances; use the project's documented schema; never touches the original), runs `dft-cli run` through subprocess with a timeout, reads results.json, and produces scan.csv and scan.json and a markdown table (point id, parameter, total energy Ha, energy per atom, difference to the finest point, HOMO-LUMO gap eV, iterations, wall time) plus a manifest.json. With --emit-qe-inputs it also writes, for each point, the matching QE input through make_qe_input.py logic (both `--fft-grid ours` and `--fft-grid auto` variants) and a manifest listing input file, sha256 and the matching our-results path, so a remote runner can execute them. Default scans: ecut list as above; grids at the default cutoff: the automatic grid plus two larger smooth grids and one just-sufficient grid (derive the candidates from results.json of a first run, document the rule); tolerance scan: density_residual_tolerance in 1e-5, 1e-6, 1e-7, 1e-8, 1e-9 with energy and eigen tolerances scaled (document). Tests use a synthetic UPF and tiny cell written to a temporary directory and the real built binary found via the --dft-cli argument (tests skip with a clear message if the binary is not built; the check script builds it).
