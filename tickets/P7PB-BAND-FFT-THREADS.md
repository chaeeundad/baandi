TASK_ID: P7PB-BAND-FFT-THREADS
GOAL: Parallelism inside one k point, deterministic, using the standard library only (std::thread::scope; no OpenMP, no rayon, no new dependency), so that few-k-point calculations (Gamma, supercells) also use several cores. Today the user-visible thread count (`[scf] threads = N`, default 1) only distributes k points (P7P6, P7PA, merged); with one k point everything is sequential. Expected workloads: a bigger cell (for example the 8-atom conventional silicon cell, about 48^3 grid and 20 bands) at Gamma.
OWNED_FILES: crates/dft-physics/src/hamiltonian.rs and its tests (block apply with per-thread scratch), crates/dft-solvers/src/lib.rs ONLY where Davidson applies the operator to blocks (use the existing block entry; no algorithm change), crates/dft-engine/** (thread budget split, density accumulation over bands), crates/dft-numerics/** (only for the optional lane-parallel FFT experiment, below), crates/dft-cli/** (reporting of the thread split), scripts/bench_scf.py (additive: a new case `si8` and, if needed, an option to name a binary pair; keep defaults), docs/cli.md (append), docs/decisions/0001-numerical-backend-isolation.md (append "P7PB notes"), docs/performance/optimization-log.md (append). Do not touch manifests, Cargo.lock, tickets/, artifacts/, baselines, README.
DESIGN:
1. Thread budget: `threads` stays the TOTAL budget. Split it deterministically: outer = min(threads, number of k points) workers over k points (as now), inner = max(1, threads / outer) threads available inside each k point. Report both in results.json (additive fields in the existing `threading` block) and in docs/cli.md. threads = 1 keeps everything sequential and unchanged.
2. Band-level parallelism: the Hamiltonian applied to a block of vectors is a set of independent vector applications (each: scatter to the grid, inverse FFT, multiply by the local potential, forward FFT, gather, plus the kinetic term and the nonlocal projectors). Apply them concurrently with up to `inner` scoped threads, each with its own scratch (FFT plan scratch, grid buffers, projection buffer), created once per Hamiltonian (a pool sized by the inner thread count, no allocation per call). The result of every vector is computed by the same sequence of floating-point operations as now, so the block result is bit-identical to the sequential block. Do not parallelize inside GEMM or orthonormalization (small matrices; not worth it) unless a measurement shows otherwise.
3. Density accumulation over bands inside one k point: compute the per-band real-space contribution concurrently (up to `inner` threads, per-thread scratch) and then add the contributions into the accumulator sequentially in ascending band order, exactly as the current code does, so the sum is bit-identical.
4. Optional experiment (FFT lanes): inside one transform, distribute independent lanes over threads (the lanes of one pass are independent: same arithmetic, so results stay bit-identical). Spawning scoped threads per transform costs tens of microseconds, so use it only above a grid-size threshold that you determine by measurement (state the threshold; the production grid 25^3 transform takes well below a millisecond, so expect it to be useless there). Evaluate on the 8-atom cell. Keep it only if it clearly helps beyond the band-level parallelism, otherwise reject it with the numbers.
5. Nested parallelism must never oversubscribe: outer workers x inner threads <= threads.
TESTS: bit-identity across thread counts 1, 2, 3, 4, 8 on synthetic problems with 1 k point and with several k points (all outputs compared by exact equality: eigenvalues, eigenvectors, densities, energies, histories, iteration counts), including thread counts that do not divide the band or k count; the block apply equals the sequential block apply bitwise on random vectors for Gamma and shifted-k bases; scratch pool reuse (pointer stability across calls); no thread outlives its scope; error propagation deterministic (lowest failing band or k index); scripts/check.sh green; no unsafe, no new dependency.
