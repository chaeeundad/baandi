TASK_ID: P6D-DENSITY-COMPARE
GOAL: Provide a reproducible, tested comparison of our electron density with QE's in Fourier space. QE's native `charge-density.dat` stores the Miller indices and rho(G) (e/Bohr^3) of the density, so no pp.x and no FFT grid are needed. A first real summary extracted from QE 7.6 is stored as evidence (tests/reference/si30_ours/density/qe_rhoG_summary.json); our density is tests/reference/si30_ours/ours/density.bin with density.json. Build (1) a strict reader for the QE file format, (2) an independent computation of our rho(G) from density.bin, (3) the comparison tool and its tests, including a regression test on the real evidence.
OWNED_FILES: scripts/compare_rhog.py, scripts/qe_rhog.py (reader and helpers), scripts/tests/test_rhog.py, tests/reference/README.md (append a short section), docs/validation.md (do NOT edit; Claude records results). Do not edit anything under tests/reference/si30_ours/ (evidence). Python standard library only, run with `python3 -I`; no Rust changes.
FORMATS:
- QE charge-density.dat (QE 7.x, non-HDF5), little endian, four Fortran sequential records, each with a 4-byte int32 length marker before and after the payload: (1) int32 gamma_only, ngm_g, nspin (payload 12 B); (2) b1,b2,b3 as 9 float64 (72 B; QE's units, include 2*pi, not used for the comparison); (3) mill(3, ngm_g) int32 in Fortran order, i.e. the triplet (m1,m2,m3) of G number 1, then of number 2, ... (12*ngm_g B); (4) rho(G) as complex128 (re, im pairs), nspin*ngm_g values (16*ngm_g*nspin B). The reader must verify all markers (leading equals trailing, expected sizes derived from ngm_g and nspin), consume the file exactly (no trailing bytes), reject gamma_only != 0 and nspin != 1 with explicit errors, reject duplicate Miller triplets, and never guess.
- Our density: density.json (dtype f64, endianness little, fft_grid [n1,n2,n3], ordering C: index (i*n2+j)*n3+k with k fastest, units electrons per Bohr^3, normalization block) and density.bin (little-endian float64). Grid point r = (i/n1) a1 + (j/n2) a2 + (k/n3) a3. Our reciprocal coefficients follow the project convention (docs/physics-conventions.md): n(G) = (1/N) sum_r n(r) exp(-i G.r), so n(r) = sum_G n(G) exp(iG.r), with G = m1 b1 + m2 b2 + m3 b3 and Miller wrap index m mod n on each axis. This is the same definition QE uses for stored rho(G) in e/Bohr^3 (QE's rho(G=0) equals the mean density N/Omega, which the evidence confirms to 1e-17).
IMPLEMENTATION:
1. scripts/qe_rhog.py: reader of the QE file as specified above returning a dict from Miller triplet to complex, plus metadata; a function that computes our n(G) for requested Miller triplets or for the set of Miller triplets of the QE file, by a separable 3D DFT in pure Python (cmath), independent of the Rust engine; and a function writing a synthetic QE-format file for tests (record markers, little endian).
2. scripts/compare_rhog.py with two modes: (a) `--ours-dir DIR --qe-summary SUMMARY.json` compares against the stored summary (rho(0), sum of |rho(G)|^2, max |rho(G)| for G != 0 with its Miller triplet allowing symmetry-equivalent triplets: compare the VALUE and report both triplets, never fail only because the triplet differs, and say so, plus all sample triplets); (b) `--ours-dir DIR --qe-file charge-density.dat` compares ALL stored G: maximum and root-mean-square of |dn(G)|, the relative L2 difference sqrt(sum|dn|^2 / sum|n_ours|^2), the maximum difference for G != 0 with its Miller triplet, rho(0) difference, Parseval sum difference, and the number of G present in one set and absent from the other (both must have the same set; report if not). Both modes verify before comparing: our density integrates to the expected electrons within 1e-10 (from density.json), the SHA-256 of density.bin matches the one recorded in density.json, our grid is consistent with the QE G set (all QE Miller indices representable on our grid without aliasing; state the rule you use), and for mode (a) the summary's sample list is non-empty. Default tolerances (printed in the report, overridable but any override is flagged as non-default, never loosened silently): per-coefficient absolute difference <= 1e-7 e/Bohr^3, rho(0) difference <= 1e-12, relative difference of the sum of |rho|^2 <= 1e-6, relative L2 difference (mode b) <= 1e-6. Output a markdown and a JSON report (fresh paths required; refuse to overwrite evidence). Exit codes: 0 all tolerances met, 5 comparison done and a tolerance exceeded, 3 inconsistent inputs or format violation, 1 usage or I/O error.
3. Noise-floor information in the report (informational, not a gate): for the sample triplets that are equivalent by the cubic symmetry of the diamond lattice ((1,0,0), (0,1,0), (0,0,1) have equal rho by symmetry), print the spread of the QE values and of our values, so a reader can judge whether differences are within the numerical noise of either code.
