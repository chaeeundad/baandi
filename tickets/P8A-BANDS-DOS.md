DESIGN:
1. nscf solve: given the converged SCF (density on the grid, same cell, basis, pseudopotentials), rebuild the effective potential from that density (ionic + Hartree + XC, exactly as the SCF does, through the same functions; no copy of formulas) and solve for the lowest `nbands` eigenpairs at each requested k point with the existing Davidson, using the k-parallel thread machinery (deterministic: results identical for every `threads` value). The tolerance is an eigenvalue residual (default 1e-8 Ha, option). Every k point is independent; eigenvalues are returned in Hartree with the k point list. Return per-band residuals and a converged flag; failure at a k point is a typed error naming the k index. Use the default number of extra bands but at least 4 empty bands, and tell the user about the buffer-band issue (the top band of a degenerate multiplet may converge slowly: do not make it an error as long as the plotted bands (occupied + 4 empty) are converged; if the library already has a per-band tolerance option merged from ticket P7PC when you start, use it; otherwise keep all bands strict and report non-convergence clearly).
2. Bands: `dft-cli bands input.toml` runs the SCF (as `run` does) and then the nscf solve along a k path. Path input in `[bands]`: either explicit list of labeled fractional points with a number of points per segment (or a target spacing in 1/Bohr), or a named preset for cubic lattices (fcc, bcc, simple cubic: Gamma-X-W-K-Gamma-L-U-W-L-K | U-X for fcc, the usual high-symmetry paths; give them for the primitive cell vectors the user supplies: require that the input cell matches the standard primitive fcc/bcc/sc cell up to a rigid rotation and refuse otherwise with a clear message; do not silently reinterpret). Output files in the output directory: `bands.csv` (columns: k_index, distance_inv_bohr, kx, ky, kz in fractional coordinates, then band_1..band_N in eV relative to the valence-band maximum, plus a header comment line with the units), `bands_labels.csv` (label, k_index, distance), `bands.json` (metadata: the energy reference and its value in Hartree, VBM and CBM and their k points, gap, number of electrons, bands, cutoff, k path, code version and input hash). Reference energy = VBM of the computed bands for insulators (state the definition, include the absolute eigenvalue offset in the metadata); the Fermi-level concept is not used because smearing is not implemented.
3. DOS: `dft-cli dos input.toml` runs the SCF and then an nscf on a uniform Monkhorst-Pack grid (use the existing grid generator, option for a denser `dos_kgrid`, default 2 times the SCF grid) with time-reversal reduction and the correct weights, and broadens with a Gaussian of width `sigma` (default 0.1 eV; the energy grid spacing and the window options; state the formula). Output `dos.csv` (energy_eV relative to the VBM, dos_states_per_eV_per_cell, integrated_dos) and `dos.json` metadata. Also provide the tetrahedron-free linear-interpolation alternative only if time allows; default is Gaussian.
4. Plot script: `scripts/plot_bands_dos.py bands.csv [dos.csv] -o figure.svg` makes one SVG with the band structure (labeled k points on the x axis, vertical lines at segment boundaries, energy in eV with the VBM at 0, a horizontal dashed line at 0) and, if given, the DOS on the right sharing the energy axis. Plain standard-library SVG writing (no matplotlib), readable colors, axis labels, title from the metadata; it must be robust to the number of bands and segments. The how-to document shows the commands and a picture of the Si example (generated from your own run: commit the SVG and the small CSV example under docs/examples/ ONLY if the files are small (under 200 KB) and say they were produced with the validation pseudopotential of unverified provenance: no pseudopotential file is committed).
