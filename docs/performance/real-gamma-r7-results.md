# P30A: deterministic real Gamma pair scheduling

## Scope and fixed gates

Derived from `real-gamma-design.md` sections 6 and 12, implementing R7. No QE
source was read. The motivating evidence is the relayed dev08 batch-7 B table
in `tests/reference/perf/dev08_materials_qe_relayed.md`, and the R3 block timing
observations. This changes scheduling, not the solver, tolerances or defaults.
It does not repeat rejected band-grouped FFTs or thread-dependent GEMM tiles:
each existing paired FFT is unchanged.

The frozen gates are bit identity against the saved pre-change executable at
T=1, identity across T=1,2,4,8,12, serial-pair byte identity, the complete workspace
check, and option-off identity on five benchmark cases. The R5 six-case set is
four synthetic fixtures plus primitive and conventional Si (not six additional
synthetic fixtures). Counts include main Davidson/H work and separately fresh
fixed-point certificate work. No real/complex trajectory identity is assumed.

The Mac target is real-on T=8 no slower than off, and T1/T8 scaling at least
as good as off, for both Si8 and the exact `si16-gamma.toml` case, in strict
and standard profiles. These are observations; dev08 decides acceptance.

## Implementation

`PairLocalWorkspace` reserves one `PairPlan` per fixed pair at construction.
A balanced join tree dispatches pairs (0,1), (2,3), ... onto the supplied SCF
pool. Each leaf owns its plan, packed vector and transformed vector, and writes
a disjoint output slice. An odd tail still calls the old routine with a zero
partner. Neither pairing nor floating-point operations depend on worker count.
Existing `PairPlan` and paired-density method bodies remain unchanged.

The real Hamiltonian uses this workspace. Engine boundary ORC packing and
Hermitian completion use the same fixed pair partition and disjoint slices.
There is no pool accessor addition and no CLI or other engine plumbing change.
The engine currently uses complex density on completed orbitals, already
parallel on the persistent pool; it does not call `PairDensityWorkspace`.
The latter already has four-pair pieces and ordered reduction, left unchanged.

Numerical scratch is allocated before operator applications. Scratch grows
with ceil(capacity/2), independent of thread budget, including at T=1; the
Hamiltonian snapshot is still rebuilt per eigensolve. No per-application
allocation, clocks, logging, global pool, unsafe code or new dependency is added.

Most measured solver wall time lies **outside Hamiltonian application**.

and this explicitly unclassified remainder are the basis for the next profile,
