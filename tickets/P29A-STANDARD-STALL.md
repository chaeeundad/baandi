TASK_ID: P29A-STANDARD-STALL
GOAL: Study and, if justified, fix a robustness weakness of the opt-in standard convergence profile (ADR 0035; read docs/decisions/0035-standard-convergence-profile.md, crates/dft-engine/src/convergence.rs (StandardProfile::ratchet) and the SCF loop in scf.rs, tests/reference/perf/p29a/si8_standard_histories_dev08.md, docs/performance/AGENT-BRIEF.md and the ledger first). Evidence from dev08: on si8 the standard profile needs 15 SCF iterations with the pure build but 27 with the MKL build (the two runs differ by 1.3e-16 in iteration 1 and diverge from iteration 2). In the MKL run iterations 5 to 16 stagnate: density residual stays between 3.3e-3 and 5.3e-3, the energy rises in several iterations, the Davidson step count is 2 in eight of them, and the requested eigen tolerance stays bit-identical over iterations 9 to 13 (1.5136e-04) and 15 to 17 (1.2040e-04) while the maximum eigen residual rises. Hypothesis: the tolerance ratchet min(previous, 0.1 * standard_error / electrons) only tightens when the Hartree-weighted error estimate falls; a loosely solved eigenproblem makes the output density noisy, the error estimate stalls, the tolerance stays loose: a self-reinforcing loop. The pure build got lucky on this trajectory; MKL is not available on the Mac, so the weakness must be reproduced by trajectory perturbation.
OWNED_FILES: crates/dft-engine/src/convergence.rs and scf.rs (the standard-profile tolerance logic only, additive, default behaviour unchanged), crates/dft-engine/tests/ (new test files standard_stall_*.rs), crates/dft-cli/src/config.rs and run.rs (a key `[scf] standard_stall_guard = "off" | "on"`, default off, only if the study justifies the guard), docs/decisions/0035-standard-convergence-profile.md (append an amendment section, status Proposed), docs/performance/standard-stall-study.md (new), docs/performance/attempts-ledger.md (append). Plumbing-only additive edits elsewhere in dft-engine/dft-cli are allowed and must be listed.
PHASE 1 (study, no behaviour change): build a perturbation harness (test or script; a documented hook that perturbs the starting trajectory by a tiny relative amount, for example 1e-10 relative noise on the initial density, different thread budgets, a different Davidson seed where it matters; list what you used) and run the standard profile on at least 8 different cases from benchmarks/cases and the materials fixtures (cubic, skewed, elongated, slab, 2 to 16 atoms, Gamma and k meshes, small and large gaps, synthetic fixtures where real files are missing) with at least 10 perturbations each, at default settings. Report per case: SCF iteration count distribution (min, median, max), delivered energy error against the strict tight reference of that case, work (Davidson steps, H vectors). Define a stagnation event objectively (for example SCF count above 1.5 times the case median, or density residual not falling by a factor 2 over 5 consecutive iterations) and report how often it happens, whether it reproduces the MKL-like pattern (constant requested tolerance while the density residual stalls), and show two example histories. If no stagnation is found on the Mac, say so plainly and stop Phase 2 unless the harness can produce the pattern.
PHASE 2 (only if Phase 1 shows stagnation events): implement a stall guard as an opt-in switch inside the standard profile: when the standard error estimate has not decreased by at least a stated factor over a stated number of iterations, the requested eigen tolerance is tightened by a stated factor (choose the parameters from the study, do not tune on a single case; justify them with the whole perturbation set and a held-out set of cases not used for the choice). The default (guard off) must stay bit-identical. Evaluate with the same perturbation set: SCF count distribution, delivered accuracy (still within the standard profile's bound, report against the same tight references), and work, compared with guard off. Also check that cases that never stagnate are not made slower (report the change in median work). Report honestly if the guard costs more than it saves.
GATES: scripts/check.sh all exit 0; bench_scf --require-identical for the default path (five standard cases, thread budgets 1, 2, 4, 8, 12, strict and standard profile with the guard off); no tolerance of the strict profile or of the certificate changed; standard results stay labelled uncertified. Do not create extra target directories; write raw evidence outside target (../rust-dft-wt/archive/P29A-evidence/).
