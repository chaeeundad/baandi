1. In dft-numerics add a sparsity pattern type built once from the list of nonzero grid indices (for example `SpherePattern::from_indices(shape, &[[usize; 3]])`) that precomputes, for the project axis order 0, 1, 2, which lanes are needed in each pass. The axis order and the per-lane arithmetic must not change (bit-identity). For the inverse (reciprocal to real) transform of an input that is zero outside the pattern: pass 1 (axis 0) only lanes (j,k) that contain a nonzero input; pass 2 (axis 1) only lanes (i,k) with k present in the pattern; pass 3 (axis 2) all lanes.
