PHYSICS_CONVENTIONS (write these into docs/physics-conventions.md and implement exactly):
1. Units: Hartree atomic units internally. 1 Ha = 2 Ry exactly. Bohr radius in Angstrom as a single named constant with its source documented (use CODATA 2018, 0.529177210903 Angstrom, and say that QE comparison in P6 must confirm the constant QE uses; do not claim equality now). Provide conversions Bohr<->Angstrom, Ha<->Ry, Ha<->eV with the eV constant and its source documented. Use newtypes or clearly named functions so units cannot be mixed silently.
2. Lattice: A has the lattice vectors a1, a2, a3 as COLUMNS (internal, Bohr). The TOML/user-facing `lattice_vectors` list gives one vector per ROW; the constructor that takes user rows must convert and document this. Volume = |det A|; reject non-finite or near-singular cells with a typed error (state the threshold). Reciprocal B = 2*pi*inverse(A)^T so that a_i . b_j = 2*pi*delta_ij. Fractional <-> Cartesian conversions for positions. Left-handed cells (det < 0) are accepted; B stays consistent.
3. Plane waves: psi(r) = Omega^(-1/2) * sum_G c(G) exp(i G.r), sum_G |c(G)|^2 = 1.
4. FFT grid and convention: grid dimensions (n1, n2, n3); array layout is ndarray row-major (C order) Array3<Complex64> with index (i, j, k), flat = (i*n2 + j)*n3 + k. Grid point r = (i/n1) a1 + (j/n2) a2 + (k/n3) a3. Define the two transforms on this grid:
   - to_real (G -> r): f(r) = sum_G f(G) exp(+i G.r), NO scale factor.
   - to_reciprocal (r -> G): f(G) = (1/N) sum_r f(r) exp(-i G.r), N = n1*n2*n3.
   Map ndrustfft onto this by measured behavior (rescale where needed). Parseval in this convention: sum_r |f(r)|^2 = N * sum_G |f(G)|^2; state and test it. Index-to-frequency rule for an axis of length n: index m represents frequency m for m <= (n-1)/2 (integer division) and m - n otherwise; document the Nyquist handling for even n (frequency n/2 is represented at index n/2 as -n/2 by this rule; state it).
5. A plan object holds the ndrustfft handlers and scratch buffers and is reusable across calls (no per-call plan construction). A trait for the 3D FFT backend is welcome but keep it small.
