TASK_ID: P8G-INPUT-PREFLIGHT
GOAL: A preflight check that makes wrong or misleading inputs fail early with a clear message instead of running a different calculation than the user intended. Found by the survey docs/research/feature-gap-survey.md: a species labeled Fe can be bound to the silicon pseudopotential and the run succeeds; `validate` accepts invalid SCF settings. Read that survey (tables T1 and T2 and the robustness experiments), docs/cli.md, docs/upf-support.md, crates/dft-cli/src/config.rs and run.rs, crates/dft-upf (header fields: element, valence, functional, suggested cutoff metadata if present).
OWNED_FILES: crates/dft-cli/src/preflight.rs (NEW) with minimal wiring in config.rs/run.rs/main.rs (other tickets, P8A and P8B, add config tables and run wiring in parallel: keep your edits to a few lines each and say exactly which), crates/dft-cli/tests/preflight.rs (NEW), crates/dft-upf/src only for exposing already-parsed header fields through accessors if needed (additive), docs/cli.md (append), docs/decisions/0022-input-preflight.md (NEW). Do not touch other files, manifests, Cargo.lock, tickets/, artifacts/, baselines, README.
DESIGN:
1. Species identity: each species label is checked against the element recorded in its pseudopotential header. A label that is not a chemical element symbol (for example a custom tag such as `Fe1`, `Si_up`) is allowed only with an explicit `element = "Fe"` key on the species/pseudopotential entry (additive TOML key, documented) and the element is then checked against the UPF header. A mismatch is an error with an actionable message that names the label, the file, the header element and how to fix it; an explicit override `allow_element_mismatch = true` exists for deliberate tests and is recorded in results.json and printed (never silent). Atomic masses/numbers are not needed by the engine today; do not add physics.
2. `validate` becomes the full preflight (it must not read dense data or run SCF): geometry and cell checks that exist today, SCF option validity (the same checks `run` applies at ScfProblem construction: tolerances positive, mixing parameters, thread counts, band counts versus electrons, odd electron count, impossible cutoffs), k-point specification, species/pseudopotential files present and parseable, identity check, functional check against the UPF label (the existing override rule), minimal cutoff warning using the UPF suggested-cutoff metadata when the file has it (warn, not error; state the rule), estimated memory and number of plane waves/FFT grid, and a final summary of "what will be computed" in plain language (material composition, number of atoms, electrons, functional, k mesh, cutoff, bands, threads). Exit codes: 0 valid (possibly with warnings), the existing usage/validation code for errors; warnings never change the exit code but are printed and listed in a machine-readable `--json` report.
3. `run` performs the same preflight first (single code path), so the two cannot diverge; the preflight report (warnings, overrides) is stored in results.json (additive field).
4. Error messages follow one style: what is wrong, where (TOML key path), why it matters, how to fix; tested for the cases below.
TESTS: Fe label with the Si UPF fails with the identity message (use the synthetic pseudopotential fixtures of the repository, never a real UPF in tests; an ignored release test may use the validation UPF through an environment variable, never committed); custom label with explicit element passes and mismatching explicit element fails; the override is recorded; each SCF-option error case of the survey is rejected by `validate` with the key path; odd electron count; band count too small; cutoff warning; the plain-language summary content; exit codes; JSON report schema; all existing tests stay green and the existing example inputs still validate; scripts/check.sh green.
ACCEPTANCE_CRITERIA: the survey's failing cases now fail early with clear messages, valid inputs behave as before (results unchanged), documentation and ADR 0022 written, no new dependency, no unsafe.
NON_GOALS: new physics, pseudopotential registry and downloads (a later ticket), natural-language input (ticket P9A designs it), performance work.
GIT: Leave changes uncommitted and say so.
RETURN_FORMAT: docs/schemas/report.schema.json. Real exit codes only.
