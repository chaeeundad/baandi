TASK_ID: ONEPATH-2B-CELL-RELAX-GRID
GOAL: Fix the dev08 failure of variable-cell relaxations on the standard path (binary 7a58d83, real Si8 PBE, mode cell isotropic and ions_cell): the standard arms failed at step 3 with Numerical("Miller index [0, 0, 18] is outside the canonical frequencies for [36, 36, 36]") while the strict reference converged.
ROOT_CAUSE: `CoulombMetric::new` (crates/dft-engine/src/convergence.rs), the Hartree-metric estimator of the standard stop rule (built for every standard problem in `ScfProblem::construct`, never on the strict path) and of the optional Hartree mixing metric, built its density sphere from the CURRENT cell at 4 x cutoff, ignoring the frozen Miller reference (`ScfOptions::strain_reference`) that a variable-cell relaxation uses together with a frozen FFT grid (`grid_override`). After a cell expansion that sphere holds larger Miller indices than the frozen grid represents, so problem construction failed for every attempt of that step. Not the cutoff ladder, REUSE_PSI, potential reuse, the lean projection cache, the lean apply or real Gamma (each switched off on the real file; failure unchanged; a backtrace located the metric).
FIX: the metric takes the problem's options and uses its own density list, `options.basis(cell, 0, 1).density_basis(cell)` (the frozen reference set expressed in the current cell when a reference is present; otherwise the same 4 x cutoff sphere of the cell as before, so ordinary runs are unchanged bit for bit). The three construction sites (stop rule, Hartree-metric Pulay, Hartree-metric Kerker-Pulay) pass the options. No tolerance, threshold or strict-path arithmetic changes (the strict path never builds the stop-rule metric; Hartree mixing is opt-in).
OWNED_FILES: crates/dft-engine/src/convergence.rs (CoulombMetric::new and its unit-test callers), crates/dft-engine/src/scf.rs (one call), crates/dft-engine/src/session.rs (two calls), crates/dft-engine/tests/frozen_cell_metric.rs (new), crates/dft-cli/tests/onepath_stress.rs (real-file release check), crates/dft-cli/tests/cell_relaxation.rs (`combined_scf_enthalpy_derivative`: after main's ONEPATH-4 its `run::options` became standard and the 1e-7 analytic-vs-FD oracle failed (2.5e-5 at 5e-9 Ha, 2.4e-7 even at 5e-13); it now sets the strict reference options explicitly, as accuracy gates do; bound unchanged, 5.0e-10 measured), docs/user/cell-relaxation.md, docs/performance/requests/onepath2b-cell-relax.md (new), docs/performance/attempts-ledger.md (row ONEPATH-2B), artifacts/task_titles.json, this ticket.
