TASK_ID: RELAX-STOP-RULE
GOAL: Native ionic relaxation stops when the target is reached, with the convention of ASE/VASP, and native FIRE uses sensible step units. User decision 2026-11-27 (option A), from the PRELAX-P0 audit (docs/roadmap/precon-relax-audit.md) and PRELAX-P1 stages 1-2 on dev08: the native BFGS reaches 0.02 eV/A (max atomic force norm) at evaluation 12/17/16 (medians) but stops only after 17/22/22-40 because (a) the force test uses the max free Cartesian COMPONENT and (b) it also requires |dE| < energy_tol on two consecutive accepted steps; native FIRE takes ~97x smaller steps than ASE FIRE for the same dt because the ASE dimensionless parameters are applied in Hartree atomic units, and needs 3.6-4.2x the evaluations of native BFGS.

CHANGES:
1. Force criterion: converged when max over free atoms of the Cartesian force NORM |F_i| (after constraint projection) <= force tolerance. Keep the old rule selectable (e.g. `force_criterion = "norm" | "component"`, default "norm"); document that norm is stricter than component by up to sqrt(3) at equal tolerance.
2. Energy criterion: not required by default. Keep it as an option (e.g. `energy_tolerance` unset/None by default = off; when set, the existing two-consecutive-step rule applies in addition to the force rule). Cell relaxation stress criteria are unchanged.
3. FIRE units: express the FIRE time step and max step so that a given input dt/maxstep moves atoms like ASE FIRE does in eV/A units (state the conversion and the defaults; derive from units, not tuned on one system). Keep the old behaviour reachable only if needed for a test; otherwise replace.
4. Logs/frames: record the max atomic force norm per step (and the component max), and the per-step wall if cheap (audit found neither recorded).
5. Docs: docs/cli.md (relax keys), an ADR (next free number) with the PRELAX evidence and the semantics change, CHANGELOG/README only through the existing generators if applicable.
6. Tests: unit tests for the criterion (norm vs component, constraints, energy option on/off), FIRE step size vs the unit conversion, and update existing relaxation tests whose expected step counts/stop reasons change (state each change and why; do not loosen accuracy assertions on final forces/energies). Tests > ~10 s in debug are #[ignore] with the release command.
