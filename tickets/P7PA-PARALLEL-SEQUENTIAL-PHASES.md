TASK_ID: P7PA-PARALLEL-SEQUENTIAL-PHASES
GOAL: Remove the sequential bottleneck left after the deterministic per-k-point threads (P7P6, merged). Measured on the quiet 80-core node for the 32-k-point case: with 16 threads the diagonalization takes 0.85 s but the engine time is 3.04 s, so about 2.2 s of the run is still sequential (density accumulation, the total-energy audit loops over k, the per-k setup of the Hamiltonians and projector tables, the fixed-point certificate step, mixing). On one thread the same phases are about 20 to 25 percent of the run. Parallelize every per-k-independent part, deterministically.

Do not touch manifests, Cargo.lock, tickets/, artifacts/, baselines, README, dft-numerics (another ticket edits its FFT).
STEP 0 (measure first, put the table in the log): per-phase wall time for the benchmark cases at threads 1 and 8 (the results.json phase timers plus any additional internal timers you add for setup, certificate and per-k loops; timers only at phase boundaries, never inside numerical loops), so the sequential parts are identified by data. On this machine use the bench script's `--threads` option.
DESIGN:
1. Per-k independent work to parallelize with std::thread::scope exactly as in P7P6 (same thread-count option, default 1 stays sequential and must not change behavior): (a) setup of the per-k states in ScfProblem::new (basis, Hamiltonian, nonlocal projector tables), (b) the per-k part of density accumulation (orbitals to real space and |psi|^2 per band), (c) the per-k part of the energy audit (kinetic, nonlocal and band terms), (d) the certificate step solves (the same Davidson calls as in the iteration), plus anything else the measurement in Step 0 shows.
2. Determinism: the results must be bit-identical for every thread count, INCLUDING threads = 1. Reductions over k (density sum, energy sums) must therefore use a fixed association that does not depend on the thread count: compute per-k partial results independently (per-k density array, per-k energy contributions), then sum them in ascending k order sequentially (or with a fixed binary tree defined by k index, never by thread). The sequential code path (threads = 1) must use the same reduction structure, so T=1 equals T=N. This changes the floating-point association relative to the current main (the density is now a sum of per-k partial arrays instead of one running accumulation): that is accepted and must be reported; the gates below apply.
3. Memory: per-k partial density arrays cost one grid-size array per k in flight; bound the number of simultaneously live arrays by the thread count (process k points in chunks and add the finished partials in k order) and state the bound.
4. Report the phase table at threads 1, 4, 8, 16 (16 only if this machine has the cores; the 80-core node is measured by Claude) and the new engine time for the benchmark cases and k444s.
