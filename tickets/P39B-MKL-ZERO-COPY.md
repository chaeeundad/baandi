TASK_ID: P39B-MKL-ZERO-COPY
GOAL: Remove the buffer copies inside the MKL FFT adapter and give MKL builds a copy-free in-place transform path. dev08 measurement (tests/reference/perf/dev08_materials_qe_relayed.md, section "raw FFT rates"): `dft_mkl::Plan3d::transform` copies the input into an internal buffer and the result back, which inflates every MKL FFT call by 23 percent (36^3: 191.1 us versus 147.3 us for a pure in-place `DftiComputeBackward`) and 33.5 percent (72x36x36: 486.3 versus 323.3 us); at 25^3 there is no difference. The MKL adapter is used by every full-grid FFT of an MKL build (the complex path through `GridFusedPlan<FftPlan3d>` with `FftPlan3d = MklFftPlan3d` and the real path's pair plan under the `mkl` feature). Removing the copies cannot change any value (a copy is exact), so MKL builds must stay BIT-IDENTICAL to before. Read crates/dft-mkl/src/adapter.rs (unsafe FFI, documented preconditions), crates/dft-numerics/src/mkl_backend.rs, the `Fft3d` trait in crates/dft-numerics/src/lib.rs, crates/dft-numerics/src/fused.rs (`GridFusedPlan`), docs/decisions/0019 (MKL ADR), docs/performance/AGENT-BRIEF.md and the ledger (A34, A35 and the MKL rows). Note: FFTW is GPL and must not be added to the project; it was only a measurement reference. This Mac has no MKL: the work is compile-checked here (`cargo check --features mkl` and clippy with the feature if the toolchain allows) and the runtime tests are run on dev08 by the orchestrator, so write the tests so that they run there and document the exact commands.
WORK: (1) in dft-mkl add an in-place transform on a caller-owned buffer (documented safety: committed in-place descriptor, contiguous buffer of exactly the planned length, uniquely borrowed; no copy), keeping `transform` for compatibility; (2) extend `Fft3d` with an additive in-place method (for example `transform_in_place(&mut self, data: &mut Array3<Complex64> or &mut [Complex64], inverse: bool)`) whose DEFAULT implementation preserves today's behaviour exactly for the pure-Rust backend (no change of any arithmetic), and whose MKL override calls the new in-place primitive; (3) make `GridFusedPlan` (and any other full-grid user in dft-numerics that currently transforms between two separate arrays and could work in place on its own scratch array) use the in-place method where it is value-identical (the scratch array already holds the data to transform and its previous content is not needed afterwards), without changing the order of any operation; (4) the pure-Rust build must be bit-identical to before (bench_scf --require-identical on gamma, k222s, k222, k444s, si8 at thread budgets 1, 2, 4, 8, 12); the MKL build must be bit-identical to the previous MKL build: provide a test (ignored unless the `mkl` feature is on) that compares the new in-place path against `Plan3d::transform` on random arrays and on the pruned pattern, bit for bit, for shapes 3x4x5, 25^3, 36^3, 72x36x36 and a non-cubic odd shape, and a microbenchmark (ignored, documented dev08 command) that prints median/min/max microseconds per call of the old wrapper path versus the new in-place path at 25^3, 36^3, 72x36x36 (32 samples).
OWNED_FILES: crates/dft-mkl/src/adapter.rs (new function only; unsafe allowed there with documented preconditions), crates/dft-mkl/src/lib.rs and keep.rs only if needed, crates/dft-numerics/src/mkl_backend.rs, crates/dft-numerics/src/lib.rs (trait extension with a default method), crates/dft-numerics/src/fused.rs (GridFusedPlan use of the in-place method only; the pure-Rust ordered and plane plans untouched), tests under crates/dft-mkl/tests/ and crates/dft-numerics/tests/ (new), docs/performance/p39b-results.md (new, includes the dev08 commands), docs/performance/attempts-ledger.md (append). Plumbing-only additive edits elsewhere allowed and must be listed. Do not modify artifacts/*. P39A runs concurrently and owns fused_pair_plan.rs, real_gamma.rs and the pair microbenchmark test: do not touch those.
