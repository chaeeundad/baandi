TASK_ID: P7P6-KPOINT-THREADS
GOAL: Parallelize the independent per-k-point eigensolves of the SCF over threads, deterministically. In ScfProblem::step_kpoints (crates/dft-engine/src/scf.rs) every k point has its own state (basis, Hamiltonian with its own scratch, warm-start orbitals) and its own Davidson solve; the solves do not depend on each other within one SCF iteration. They are about 70 to 90 percent of the run time. QE 7.6 in the reference runs uses 4 MPI processes; rust-dft currently uses one thread. Use only the standard library (`std::thread::scope`): no new dependency.
OWNED_FILES: crates/dft-engine/** (scf.rs and tests), crates/dft-cli/** (TOML `[scf] threads`, results.json threading record, docs), docs/cli.md (append), docs/decisions/0001-backend-isolation.md and 0004 only to append a short "P7P6 notes" section, docs/performance/optimization-log.md (append your entry). Do not touch other crates (if Send/Sync bounds are needed in dft-physics or dft-numerics types, report exactly which and why instead of editing them; small additive `unsafe`-free changes there need a separate approval), manifests, Cargo.lock, tickets/, artifacts/, baselines, README. Another ticket (P7P5, norm and orthonormalize) edits dft-numerics/src/linalg.rs in parallel: stay out of it.
DESIGN:
1. A new option `threads` (ScfOptions additive field, default 1 which must reproduce the current behavior and the current outputs exactly; TOML `[scf] threads = N`, with 0 or an absent key meaning 1; reject nonsense; do not default to all cores). With threads > 1, run the per-k solves of one SCF iteration (and of the final fixed-point certificate step) in parallel with std::thread::scope over contiguous or strided groups of k points; each thread uses only its own k states (disjoint &mut), the solver and Hamiltonian code stays sequential inside a thread (faer uses Par::Seq, FFT is serial: no nested parallelism).
2. Determinism is the hard requirement: the results (eigenvalues, orbitals, residuals, iteration counts, density, energies, history) must be BIT-IDENTICAL for every thread count, and bit-identical to the current main with threads = 1. Therefore only the Davidson solves are parallel; everything that accumulates over k (density, energies, weights, mixing, certificate sums) keeps exactly its current sequential order and arithmetic after the solves finish. Collect per-k results in k order. Errors: if any solve fails return the error of the lowest k index (deterministic), after all threads have joined; no thread outlives the scope.
3. Report threading in results.json (`threading` block: threads requested and used, backend description) additively; legacy fields stay; document in docs/cli.md. Timings: keep the phase timers meaningful (wall time of the parallel region in diagonalization_s; mention it).
4. Cap the used threads at the number of k points; the Gamma case stays single-thread.
TESTS: (a) bit-identity across threads = 1, 2, 3, 4, 8 on a synthetic multi-k problem (all outputs compared field by field with exact equality) and on a case with fewer k points than threads; (b) threads = 1 equals the output of the unchanged previous code path (keep a reference run recorded in the test as data or compare against a second code path); (c) error propagation: a solve that fails at k index 2 and 3 reports index 2 regardless of scheduling; (d) no thread panics leak (a panicking solve becomes an error or propagates deterministically: state what you chose); (e) all existing tests green; scripts/check.sh green; no unsafe, no new dependency.
