GOAL: Add the named compatibility switch `[compat] mode = "reference"` that selects, in one line, the four existing conventions that make BAANDI's energies comparable with the external reference plane-wave code used in the validation studies. The user approved this switch on 2026-11-08 and asked that the name must NOT use the other code's name directly: use the neutral word `reference` in keys, messages, docs and result metadata (the other code may be named only in evidence documents that cite measurements). Read docs/decisions/0036-pw92-prefactor-convention.md, 0037-radial-convention-options.md, docs/validation/xc-prefactor-diagnostic.md, radial-convention-score.md, symmetry-full-group.md, tests/reference/perf/dev08_materials_qe_relayed.md (the evidence: with all of them on, Si and MgO totals agree with the reference to the 1e-8 Ry level; the k444s symmetry shift is reproduced to 1.0e-9 Ha), AGENT-BRIEF.md and the existing option implementations (crates/dft-cli/src/config.rs, run.rs, preflight.rs, checkpoint_io.rs; crates/dft-engine options).
MODE CONTENT (exactly these four, no new numerics): `[xc] pw92_prefactor = "original"`; `[pseudo] local_mesh = "qe_like"` (keep this existing enum value, it is an established key; do not rename existing keys, they are part of recorded evidence; the mode documentation may call the convention "reference-style local mesh"); `[pseudo] radial_even_rule = "simpson_quadratic_end"`; and `[symmetry] density_group = "crystal"` only when `[symmetry] mode = "auto"` (with symmetry off or absent the density group stays at its default, because the option applies to symmetry-reduced runs only). Default of `[compat] mode` is absent/`"none"`, bit-identical to today.
