# Active-learning contract

Status: **Designed**, P11I semantic v1.0. No simulation, screening, training, evaluation or deployment pipeline is implemented. Uses [workflow records](workflow-api.md), ADR 0016 state identity and P11R's provenance/DAG/checkpoint envelopes. MLIP means any compatible provider; SevenNet is an example name, not a dependency, default or interoperability claim.

## Typed records

Common finite-value, version, digest and availability rules come from the workflow API. Records are immutable and content-addressed only after canonicalization is validated. References identify immutable manifests, not mutable filenames or model aliases.

`model_family_digest` deliberately excludes geometry so a training corpus can span structures, while retaining pseudopotentials, XC, spin, occupation, charge policy, cutoff/grid recipe, k-sampling recipe, energy reference and environment/accounting conventions. Each label still retains its complete model fingerprint, including geometry and actual grid/k set. Partitioning is not permission to rank energies of different ESLE fingerprints. Any deliberate change in numerical model or producer creates a separate partition and an explicit alignment/combination recipe with validation; no implicit common energy zero.

## Stage transitions and required gates

All stage interfaces are **Designed**; their executors are **Deferred**. Map stages to P11R DAG nodes and preserve node statuses pending/ready/running/succeeded/failed/cancelled/blocked. The P11R initial node enum does not yet include screening/training/evaluation/deployment: enable those only in an explicitly negotiated schema revision with registered typed handlers. No arbitrary-code/shell node or silently accepted enum extension.

1. **MLIP simulation -> candidates.** Freeze weights, model identity, simulation recipe and state policy for a batch. Record trajectory lineage and attempted frames. Invalid or out-of-domain predictions stop or quarantine under policy. A model update cannot replace weights inside an active batch invisibly.
2. **Candidate screening -> label requests.** A versioned policy may use diversity, deterministic rules, optional uncertainties or a human decision. Missing uncertainty is not zero uncertainty. Uncalibrated ensemble spread can guide a documented heuristic but is not a probability or confidence guarantee. `calibrated=true` requires an applicable calibration record tied to exactly this producer/estimator and domain, coverage and held-out evidence; otherwise false with a reason. P11R's uncertainty `status` is derived: absent -> unavailable, false -> uncalibrated, true -> calibrated. Contradictions are rejected.
3. **DFT labeling -> label records.** Negotiate every requested property before spending the budget. Current engine energy/density/eigenvalues do not authorize forces or stress. A force-required dataset blocks or records missing forces for a separately declared energy-only use; it cannot train force targets from zeros. Only the existing fixed-point certificate creates a certified label. Retry preserves failed attempts and records any changed initialization/model. ESLE state targeting/continuation is deferred: present runs must retain unresolved labels rather than pretend a requested electronic branch was found.
4. **Dataset validation -> immutable dataset.** Verify schema, finite values, shape/units, atom mapping, complete identities, hashes, convergence certificate and property availability. Recompute density charge when density is retained; validate energy scope/reference and derivative consistency with the declared functional. Check permissions and duplicates, preserve state distinctions, quarantine inconsistent entries with reasons. Store report counts and record IDs for accepted/quarantined/rejected entries. Certificate passing is numerical convergence, not proof of physical adequacy.
5. **Training -> staged model.** Input is an immutable validated manifest, split, recipe, seed and property mask. Use only available targets; missing labels cannot become zeros through masking errors. If several electronic states occur at one geometry, require explicit state conditioning or separate state-specific datasets/models. A geometry-only target must explicitly select a documented state subset or reject ambiguity, never average distinct states. No claim of global ground state follows from selecting the lowest observed converged energy.
6. **Evaluation -> deployment eligibility.** Predeclare thresholds and splits before fitting. Keep correlated trajectory frames, identical geometries with multiple states, and descendants in the same split to prevent leakage. Report per-species, cell shape, size, state, gap/domain and property strata as applicable, plus worst cases; one pooled error is insufficient. Energy metrics name total versus per-atom unit/reference; force metrics identify norm/reduction and eV/Angstrom or Ha/Bohr. Evaluate stability and out-of-domain rejection on the intended simulation domain. No universal numerical thresholds are invented here.
7. **Controlled deployment -> next simulation batch.** Require passing evaluation and recorded authorized approval. Bind an immutable model digest, permitted domain, monitoring policy and rollback target. Activate atomically at a batch boundary; record any MD continuation/reinitialization and energy discontinuity assessment in the simulation recipe. Failure retains the old deployment; rollback is an audited change. Fresh deployment invalidates prior calibration unless applicability is explicitly established. No silent averaging, replacement, delta correction or fallback from DFT to MLIP.

## ESLE identity and provenance

Keep request, attempt, geometry, evaluated electronic state and branch identities distinct. Same geometry is not same state. SAME/DISTINCT/UNRESOLVED comes from a validated ESLE comparator at identical model fingerprint with measured tolerances; energy proximity alone is never a merge rule. UNRESOLVED records remain separate. Even SAME records retain attempts and provenance; deduplication may reference one payload while preserving their identities. Different environments mean different models; a warm transfer does not authorize equal-model energy ranking.

Every DFT label's P11R `ProvenanceRecord` must retain source commit/code version, dirty patch hash when dirty, input SHA-256, exact pseudopotential SHA-256 per species (no UPF bytes), model/environment digests, compiler/lockfile/backend, execution/thread identity, seed, initialization lineage, policy-log digest, output manifest references, status and certificate presence. The associated QualityRecord carries actual certificate residuals/criteria and a link to the source calculation. Validation verifies references, not just a supplied `passed=true`. Unknown/missing pseudo identity or certificate quarantines a purported certified label. Every MLIP prediction names weights, training manifest and recipe rather than impersonating a DFT label.

Durable arrays use binary references under P11R; labels and structures should additionally be exported in standard interoperable formats (e.g. extxyz with explicit units/properties) when separately implemented and independently reader-tested. Sidecar manifests preserve identities, state labels, unavailable-property reasons and provenance that a target format cannot represent. Format loss is documented, never silently discarded.

## Required tests and exclusions

Before enabling the pipeline, test stale/different weights, missing calibration, mismatched calibration domain, deliberate split leakage, two states at one geometry, unresolved-state retention, unknown hashes, failed certificates, missing forces, mismatched energy reference, property masking, duplicate attempts, dataset mutation, unsupported DAG nodes, deployment rejection and rollback. Require exact recorded producer lineage through every transition and no model change on rejected deployment. Numerical label accuracy uses separately stored reference evidence; this ticket generates none.

**Deferred:** actual MLIP engines, MD integration, uncertainty calibration algorithms, state discovery, force/stress labeling, retraining service and deployment automation. **Not claimed:** a calibrated uncertainty estimator, active-learning speedup, generalization quality, autonomous scientific approval or any current force-capable dataset.
