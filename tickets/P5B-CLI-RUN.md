BEHAVIOR (document everything in docs/cli.md):
1. `dft-cli run <input.toml> [--output-dir DIR]` uses the existing TOML schema ([system], [pseudopotentials], [basis], [xc], [scf], [output]). Wire the [scf] section: max_iterations, mixing ("linear" or "pulay"; keep "linear" accepted as in the project spec, add "pulay"), mixing_beta, energy_tolerance_ha, density_residual_tolerance (the L2 norm per electron defined in physics-conventions.md; say so in docs/cli.md), and optional nbands / extra_bands, eigen_tolerance, seed with defaults. [output] directory (relative paths resolved against the current directory; `--output-dir` overrides). Unknown fields are still errors (deny_unknown_fields). Relative UPF paths in [pseudopotentials] resolve against the input file's directory. LDA-PZ only. Gamma only.
2. Pipeline: parse config, validate, read each UPF file with dft-upf (explicit unsupported-feature errors), compute SHA-256 of the input TOML bytes and of each UPF file's bytes, compute the electron count from z_valence, set faer/engine parallelism to single thread for deterministic output and record that fact, run SCF, print results, write files.
3. Console: header (system name, cell volume, Ecut in Ry and Ha, plane-wave count, FFT grid, electrons, bands, mixing), then one line per SCF iteration: iteration number, E_total in Ha and Ry, delta E, density residual, max eigen residual, Davidson iterations, wall time; then a final summary with each energy term in Ha and Ry, eigenvalues in Ha and eV with occupations, HOMO/LUMO gap if bands > occupied, converged flag, total wall time and the phase breakdown (FFT/H psi/diagonalization/density/potential/mixing/total energy as available from the engine). Print "converged" only if the engine reports convergence; otherwise print a clear NOT CONVERGED message. All printing happens after the SCF returns or via an engine progress callback that does no I/O inside numerical kernels; do not add I/O inside the hot loop.
4. results.json (serde_json, pretty): schema_version, tool name and version, git commit and rustc version captured at compile time by a std-only build.rs (fallback "unknown"), timestamp (UTC, RFC 3339; implement without new dependencies, for example from std::time and a small civil-date conversion that you test), input_sha256, per-species {name, path, sha256, z_valence, functional string from the UPF, n_projectors}, cell (lattice in Bohr as columns, volume, reciprocal), atoms (species, fractional, Cartesian Bohr), cutoff {ecutwfc_ry, ecutwfc_ha}, basis {n_plane_waves, n_density_g, fft_grid, fft_grid_overridden}, electrons, bands, occupations, xc, scf options actually used, convergence {converged, iterations, criteria values at the last iteration, per-iteration history}, energies {each term in Ha and Ry, total}, eigenvalues (Ha and eV), timings (per phase, setup, total), threading info (single thread), memory estimate (array sizes in bytes for basis, grid, bands; measured peak RSS is NOT available in-process and must be stated as such), units note. Units named in every key or in a documented units table.
5. Density file: density.bin as little-endian f64 in C order over the FFT grid (index i fastest-varying LAST, i.e. the layout of the engine's Array3 flat index (i*n2 + j)*n3 + k) plus density.json with grid dims, cell columns in Bohr, volume, units (electrons per Bohr^3), ordering, endianness, normalization (integral = N electrons, with the sum rule value), SHA-256 of density.bin. A reader test reads the files back with independent parsing code and verifies the integral and a few sample values.
6. Exit codes (document them): 0 success and converged; 1 invalid input/config; 2 unsupported or invalid UPF; 3 SCF not converged (results.json still written with converged=false and the history); 4 diagonalization or numerical failure including divergence; 5 I/O error. Error text on stderr contains the cause. On non-convergence do not print "converged".
7. `scripts/benchmark.sh`: wraps `cargo run --release -p dft-cli -- run <input>` with `/usr/bin/time -l` (macOS) to capture peak RSS and wall time, writing a small text report next to the outputs; documents that it is a measurement helper, not a gate.
IMPLEMENTATION_STEPS: implement the run pipeline in a library module with the CLI main thin; unit tests for each part; end-to-end tests.
TESTS (stated tolerances; measured values printed; no test over about 10 s in debug, heavier ones #[ignore] with a documented release command):
a. End to end with a synthetic Si-like UPF (z_valence 4, written to a temp dir) and a two-atom fcc input at a small cutoff (for example 8 Ry): run succeeds with exit code 0, results.json exists and parses, required keys present, converged = true, total energy equals the sum of terms to 1e-12, charge error below 1e-8, and the energy matches the value obtained by calling the engine API directly with the same inputs (bitwise or 1e-12).

d.
