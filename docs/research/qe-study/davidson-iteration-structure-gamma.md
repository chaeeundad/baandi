## 1. The per-iteration algorithm (regterg, gamma_only)

### 1.1 One call from c_bands
One "call" is one run of the solver for one k point (Gamma only: one per SCF step, plus one extra at the first step when the threshold is found too loose, section 5). Sequence inside a call:
1. Copy the n starting vectors (the previous SCF step's eigenvectors, rotated only at the very first call of the run, where the wavefunction initialisation has already done a Rayleigh-Ritz in the atomic span) into the basis, zero the imaginary part of the G=0 coefficient.
2. Apply H to ALL n starting vectors, always. There is no way to skip it: the stored H products of the previous call are not kept (the arrays are allocated and freed per call). This is the "init" H block: n columns.
3. Build the reduced matrices of size n: `H_red = V^T H V`, `S_red = V^T V` (S is the plain overlap because the pseudopotentials are norm-conserving; for the real-packed layout the product is one real GEMM of inner dimension 2N minus a rank-one correction for the G=0 term, which counts once, then summed over the plane-wave ranks). If the rotation flag is on (first SCF iteration only) the matrices are not diagonalised: the starting vectors are declared Ritz vectors, the reduced matrix is set to its diagonal, the eigenvector matrix to identity. Otherwise one dense generalized solve of order n gives the first Ritz values.
4. Iterate (at most 20 iterations per call, the compiled maximum):
   a. The unconverged roots are packed to the front of the Ritz-coefficient matrix. `u` = n in the first iteration (nothing has been tested yet).
   b. Corrections: for each of the u roots form the residual from stored data only, `r = (H - e S) x = HV c - e V c`; two block products over the whole basis (`V c` and `HV c`, each of shape 2N x nbase times nbase x u), no new H application. Multiply by the diagonal preconditioner (smooth positive denominator, see note 1), normalise each to unit length (sum of squares with the G=0 term counted once, allreduced over the plane-wave ranks), append to the basis. No orthogonalisation against the basis.
   c. Apply H to the u new vectors only. This is the iteration's H block: u columns.
   d. Border update: only the new block of rows/columns of `H_red` and `S_red` is computed, shape (nbase+u) x u; the matrix is symmetrised from the upper triangle.
   e. Dense generalized symmetric solve of order `nbase+u` (see 2.3), asking only for the lowest n roots.
   f. Convergence test per root (1.2). `u` for the next iteration = number of roots not passing.
   g. If u = 0, or `nbase + u > nvecx` (the basis would not hold the next block), or the iteration limit is reached: "refresh" (1.3). If u = 0 or the limit is reached the call ends there.
5. Return the n Ritz vectors (one product of the basis with the Ritz coefficients, already formed in the refresh step).

### 1.2 How convergence of a root is decided
Root i is converged when its Ritz value changed by less than a threshold between two consecutive iterations, `|e_i(new) - e_i(old)| < thr` (energies in Rydberg). There is no residual norm. The threshold is `ethr` for a band flagged occupied and `max(5*ethr, 1e-5)` Ry for a band flagged empty. The flag comes from the band-sum step of the previous SCF iteration: a band whose weight divided by the k-point weight is below 0.01 is empty (this is only done when the full-accuracy-for-empty-bands switch is off, as in the run). In the very first SCF iteration, before any band sum, all bands are flagged occupied.
Consequences:
- Convergence is tested AFTER the first correction block is added. A call that is "already converged" at its start still pays for the n init columns AND one full block of n corrections: the minimum cost of a call is `2n` H columns (264 here), with a single iteration. A test that could skip the corrections (residual at the start) does not exist.
- The test compares with the Ritz values of the PREVIOUS iteration, so in the first iteration it compares with the value from the starting vectors; for a band that was already very accurate it is passed at once. The count `u` after iteration 1 is the number of bands whose value still moved by more than the threshold when the whole block of n corrections was applied.
- Empty bands (here 4 of 132) are loose after SCF step 1 and never cost more than a few extra iterations; their absolute floor 1e-5 Ry means they stop being the bottleneck once the occupied threshold falls below about 2e-6 Ry.
- A band once converged is never corrected again in this call, but it stays in the reduced problem and its Ritz value is recomputed (and tested again) every iteration; it can become "unconverged" again in a later iteration of the same call because the flag is recomputed from scratch each time, not locked. So `u` is not monotone decreasing in principle.

### 1.3 Subspace growth, capacity and restart ("refresh")
- Capacity `nvecx = 2n` (input `diago_david_ndim`, default 2; for isolve = Davidson the driver passes `nbndx = 2*nbnd`).
- Growth: `nbase` starts at n and grows by `u` every iteration.
- The first iteration of every call adds u = n vectors, so `nbase` becomes exactly 2n = nvecx. The test `nbase + u' > nvecx` with the NEW `u'` (any `u' >= 1`) is then true: the basis is contracted immediately after iteration 1 whenever the call needs a second iteration. In the common case of a warm start this means almost every call with two or more iterations restarts once right after its first iteration, then continues with `nbase = n` and small blocks.
- Refresh: the first n basis vectors are replaced by `V c` (the n lowest Ritz vectors), the stored H products likewise by `HV c` (two GEMMs of 2N x nbase x n; no H application), `nbase` is set to n, the reduced matrices are reset to diag(Ritz values) and the identity (no dense solve is needed to restart). The Ritz coefficients for the returned eigenvectors are also formed by one more GEMM of the same shape (so a refresh costs three 2N x nbase x n GEMMs; a normal return costs one).
- After the restart, with u around 25 (section 4) and n = 132, the basis can take about (264 - 132)/25 = 5 further blocks before another restart; for the observed 1-6 iterations per call a second restart is rare.
- If the solver ends with unconverged roots (iteration limit), c_bands repeats the whole call (including a fresh init H block) up to 5 times in SCF mode when more than 5 roots are unconverged; the run reports 13 calls for 12 SCF steps, so this fall-back has most likely not triggered (the 13th call is the first-step redo of section 5).

## 2. Operations per iteration with shapes
Real-packed shapes: a block of `k` vectors is a (2N x k) real matrix; `N` per rank is about 23871/8 = 2984 (each rank holds roughly the same number of sticks and plane waves). All GEMMs are real DGEMM with inner dimension local 2N, followed by a sum over the 8 plane-wave ranks for the reduced-space products.

| Step | Shape (real GEMM) | When |
|---|---|---|
| H on block | see section 3 | n columns at init, then u per iteration |
| Border H: `V^T HV_new` | (nbase+u) x u, inner 2N | every iteration, plus rank-one G=0 fix |
| Border S: `V^T V_new` | (nbase+u) x u, inner 2N | every iteration (a second GEMM identical in shape) |
| Reduced solve | order nbase+u | every iteration |
| `X = V c_u` and `HX = HV c_u` | 2N x nbase x u (two GEMMs) | every iteration, before preconditioning |
| Preconditioner and norm | 2N x u elementwise, one allreduce of u numbers | every iteration |
| Refresh (three GEMMs 2N x nbase x n) | contraction of V, HV, return vectors | after iteration 1 (if more iterations needed), when the basis is full, and at the end (return only: one GEMM) |
| Init borders | n x n, inner 2N, two GEMMs (H and S) | once per call |

All reduced-matrix products are summed with an allreduce over the plane-wave group (one per border, of size nbase x u doubles, so small: 264 x 132 x 8 bytes = 280 kB at the largest) plus one for the u norms and one for the stored-product contractions inside a refresh if band parallelisation were active (it is not under pure MPI plane-wave distribution).
S products: for norm-conserving pseudopotentials no S application exists; `S_red` comes from the basis overlap. There is no S-matrix H-like product.

### 2.1 What is done "only for the new block"
The reduced matrices are bordered, not rebuilt: per iteration one (nbase+u) x u GEMM for H and one for S. The correction block touches only the u unconverged roots. Everything that is O(n) per iteration regardless of u is: the dense solve (order nbase+u), the symmetrisation of the reduced matrices, the convergence test, the copying of the unconverged coefficient columns to the front. The Ritz vectors for the converged roots are not formed during a call; only at refresh or return.

### 2.2 First iteration and the restart that follows
Iteration 1 is the largest: u = n = 132, so the GEMMs for borders are 264 x 132, the corrections two GEMMs of 2N x 132 x 132, the H block is 132 columns, and the dense solve has order 264 (from 132 to 264). Immediately after it the refresh (three GEMMs of 2N x 264 x 132). Counting the real flops globally: each of these GEMMs is about `2 * 47742 * 264 * 132` = 3.3e9 flops (the border ones with nbase = 132..264 in the first iteration are a half to one such unit), so iteration 1 plus refresh is about 8 to 10 GEMM-units, order 3e10 flops globally, about 4e9 per rank, i.e. of order 0.1 s per rank at 30-40 GFlops per core. This estimate (marked INFERRED, within a factor two) is the dominating non-H, non-FFT cost per call; it is the same size as one hundred and thirty FFT pairs.

### 2.3 The dense small eigensolver
- The reduced problem is generalized: `H_red c = e S_red c`. `S_red` is not the identity (no orthonormalisation of the basis), so each iteration needs a Cholesky of `S_red`, the reduction and a symmetric eigensolve.
- The routine is `rdiaghg` (LAXlib), reached through `diaghg`. It runs on ONE rank of the band group (the root of the plane-wave/ band group); the other ranks wait, then the eigenvalues and the full eigenvector matrix (nvecx x nvecx, leading dimension) are broadcast. For the real symmetric case the LAPACK drivers are `DSYGV` (all roots, used when the number of requested roots equals the matrix order, i.e. only for the n x n initial solve) and `DSYGVX` with index range 1..n (a partial solve, used whenever order > n, i.e. every iteration). The routine saves and restores the diagonal of H and S around the call because LAPACK overwrites them.
- Size and frequency: order 264 in the first iteration of every call (one solve), then orders 132 + u (about 157 at u about 25) in the later iterations. One solve per iteration, 58 iterations in total, plus the n x n solve only when the rotation flag is off (13 - 1 = 12 times at the beginning of a warm call; for the first SCF step it is skipped). So about 70 solves of order 130 to 264 per run, of which 13 of order 264 (DSYGVX asking for half the spectrum).
- Distributed variant: the parallel version (`pregterg`) only runs if the linear-algebra group is at least 2 x 2 (see `Modules/set_para_diag.f90`: needs both dimensions of the ortho grid > 1). The default size of that group is the largest square number of ranks such that the blocks are at least about 100 x 100 (`PW/src/setup.f90`): for 132 bands that gives round(132/100) = 1, so the group has ONE rank, `use_para_diag` is false and the serial `regterg` above is what runs on dev08 with 8 ranks (assuming `-ndiag` was not set on the command line; this is an assumption to confirm, question Q6).
- Cost estimate (INFERRED): DSYGVX at order 264 does a Cholesky (n^3/3 = 6e6 flops), a reduction to standard form (about n^3 = 1.8e7), a tridiagonalisation (4/3 n^3 = 2.5e7, memory bound), bisection/inverse iteration for 132 vectors and back transformation (about n^3 = 1.8e7). A total of about 7e7 to 1e8 flops at low efficiency, i.e. a few ms to about 15 ms on one core per solve. It runs replicated or on the root only; the other ranks idle during it. At 13 solves of order 264 plus about 45 of order 150 the dense solves are around 0.2 to 0.5 s of the 4.0 s total (if 69 ms x 58 is the QE c_bands time); not dominant but not negligible. Needs the cdiaghg/rdiaghg clock from QE to confirm (Q2).

## 3. How h_psi processes a block in gamma_only, and the FFT count
- h_psi on `m` columns: (1) kinetic term, elementwise `g2kin * psi` for all columns; (2) local potential through FFT (the routine named in the references, used for the gamma case also on CPU), (3) nonlocal term: projections of all m columns on all projectors (`calbec`: real GEMM, projectors x 2N, summed over ranks), then add back `beta * D * <beta|psi>` (`add_vuspsi`, a second GEMM). The block is always passed whole; the solver never splits a block (no internal blocking by size, no task-group pipelining under the settings of the run).
- Local potential, gamma trick: two real bands are packed as the real and imaginary parts of one complex wavefunction on the smooth grid (72^3 here). Per PAIR of bands: one inverse transform (G to R) of the packed complex array, multiplication by the real local potential at every grid point, one forward transform (R to G), then the two bands are separated by the usual symmetric/antisymmetric combination and added to `hpsi` with weight 1/2. An odd last band is transformed alone. So `m` columns cost `2 * ceil(m/2)` three-dimensional wave transforms: one transform per column, half inverse and half forward.
- What the pw.x clock "fftw" counts: the label is attached to every `invfft`/`fwfft` call with kind "Wave" on the smooth grid, so ONE count = ONE complete 3D transform (the internal 1D/2D passes and the transpose are inside the call). This is how 5410 should be read: not a number of 1D batches.
- The same label is used by sum_band: the density from the Ritz vectors does one inverse transform per band pair for the occupied-plus-empty bands (all `n` columns, weights are not used to skip), so `ceil(n/2)` = 66 counts per call of sum_band, and NO forward transform. The density itself is on the dense grid and uses another label (not counted in "fftw").
- The initial rotation of the starting wavefunctions applies H to all starting functions (for `startingwfc = atomic`, `max(natomwfc, nbnd)` columns: for 64 silicon atoms with s and p atomic orbitals this is 256 columns in one block) and diagonalises a (256 x 256) generalized problem. It happens once, before the SCF loop, and runs through the same h_psi.
- Pure MPI plane-wave distribution (8 ranks, no task groups, no band groups, no pools): all 8 ranks hold all bands and a slab/stick share of each; each 3D transform is a distributed transform with the plane-wave transposes (one all-to-all style scatter per direction change). h_psi on m columns is therefore m transforms, in a loop over pairs, each with its own two transposes; there is no batching of several pairs into one transform (the `many_fft` option is 1 by default). Band-group parallelisation is off, so there is no band-level split of h_psi. The reduced-matrix products use an allreduce over all 8 ranks.

## 4. Counts per call and the inference from the dev08 numbers

### 4.1 Formulas
For one call with k iterations and unconverged counts u_1, ..., u_(k-1) (u_k = 0 for a normal exit; u_j is the number after iteration j):
- H columns = n (init) + n (iteration 1, u = n) + sum over j = 1..k-1 of u_j (iterations 2..k).
- H calls (blocks) = 1 + k.
- Wave transforms inside h_psi = sum over the blocks of `2*ceil(m/2)`; for even m this is m, an odd block adds one extra transform.
- At the first SCF step ethr = 1e-2 Ry, the occupied bands start from a rotation in the atomic span: after the n corrections of iteration 1 typically a large part of the 132 still moved by more than 1e-2 Ry, so u_1 can be up to n: first step H columns = 264 + u_1 + u_2 + ... where u_1 is between 30 and 132 (not known).
- At later SCF steps with 1 to 3 iterations the call costs 264 (1 iteration) up to 264 + u_1 + u_2 (3 iterations), i.e. 264 to about 330 columns with u around 25.
- Guaranteed floor: every call costs at least `2n = 264` columns and 2 blocks. With 13 calls: at least 3432 columns, 26 blocks, 3432 transforms. The extra h_psi calls (blocks of u) are those of iterations 2.. (45 of them if 58 iterations in 13 calls).

### 4.2 Identity found by the numbers
The pw.x tally gives 71 h_psi calls. Per call the block count is `1 + dav_iter`, so for 13 calls with a total of 58 iterations: 13 + 58 = 71 exactly. The count of h_psi calls therefore agrees with every call being a regterg call and no extra h_psi call from the initial rotation having been counted (see the uncertainty below). The solver issued 71 blocks: 13 blocks of 132 (init), 13 blocks of 132 (iteration 1), and 45 blocks of u (iterations 2 and later).

### 4.3 Transforms and the average active band count (INFERRED)
Let F = 5410 (observed "fftw" calls), S = number of band sums, C = number of calls.
Scenario A (C = S = 13, rotation not in the tally): `F = F_H + 66 S` gives `F_H = 5410 - 858 = 4552` transforms in h_psi. Subtract the guaranteed `13 x 264 = 3432` (of 26 even-size blocks, no odd rounding). The remaining 1120 are the transforms of the 45 later blocks. Odd blocks add one extra transform each; with about half of the 45 blocks odd, the sum of the u values is about 1120 - 22 = 1100, so the average later block has 1100/45 = about 24 active bands (range 20 to 27 depending on the odd-count and the S count).
Scenario B (C = S = 12 plus one 256-column rotation counted among the 71 h_psi calls and the transforms): `F_H = 5410 - 792 - 256 = 4362`, minus `12 x 264 = 3168` leaves 1194 for 46 later blocks: about 25 active bands per block. If instead one of the 71 calls were the rotation with 13 calls of regterg the numbers would not close (13 + 58 + 1 = 72), which is why scenario A is preferred, with scenario B as the alternative; both give about 24 to 25.
The 76.2 transforms per h_psi call do not mean "66 pairs of forward and inverse plus others": the per-call average mixes 26 blocks of 132 columns (132 transforms each, i.e. 66 inverse and 66 forward), 45 blocks of about 24 (24 transforms each) and the 66 sum_band transforms per SCF step. As an average over the 71 calls it is (26 x 132 + 45 x 24 + 858)/71 = (3432 + 1080 + 858)/71 = 75.6, matching 76.2.
Result: total H columns applied by QE in the Davidson solver, INFERRED, about 4.4e3 to 4.55e3 (scenario A: 4552 minus odd rounding of about 22 = about 4530; scenario B: about 4340 plus 256 = 4600 including the rotation). Break-down for scenario A: 1716 init columns, 1716 iteration-1 columns, about 1100 later-iteration columns. Of the total, 76 percent is the "fixed" 2n per call. About 4.5e3 H columns correspond to 4.5e3 three-dimensional wave transforms. Uncertainty: plus or minus 150 columns from the odd-block rounding and the 12-versus-13 question; a larger error (any "fftw" call that is not in h_psi or sum_band, which I did not find in the sources of the gamma path) would shift the number but not the structure.
Comparison with BAANDI (6025 H columns in total: coarse 1753, fine 3504, verification 768):
- The relevant QE solver number is about 4.5e3 (including the init and iteration-1 blocks and every restart-free column). BAANDI's fine stage alone, 3504 columns, is 0.77 of that; fine plus coarse = 5257 = 1.17 of it. Verification (768) has no QE counterpart in the pw.x run.
- Per Davidson iteration: QE 4.5e3/58 = 78 columns, BAANDI fine 3504/58 = 60. The 99 versus 69 ms per iteration therefore cannot be explained by BAANDI applying more H columns per iteration; QE applies more. If 58 x 69 ms is QE's c_bands wall, QE's all-in cost is about 0.9 ms per H column and BAANDI fine about 1.6 ms per column (1.8 times): the gap is in the cost per column of everything else in the iteration, not in the number of columns.

## 5. The adaptive ethr schedule and the number of iterations per call
Energies in Rydberg; `dr2` is the estimated SCF error from the mixing step (a Hartree-metric squared residual in Ry), `nelec` = 256.
| SCF step | ethr used |
|---|---|
| 1 (initial) | 1e-2 Ry (internal default for an atomic starting potential; input `diago_thr_init` zero means this) |
| after step 1: first-step redo | if `dr2 < ethr x max(1, nelec)` = 2.56 Ry (almost always true after a random-ish start), set `ethr = max(0.1 dr2/max(1, nelec), 1e-13)` and run the whole step again, with the same potential and starting wavefunctions as step 1 (the previous eigenvectors are used as new start since the call is from the stored array). This is call number 13. |
| step 2 and later | `ethr = min(ethr, 0.1 dr2 / max(1, nelec))`, with `ethr` reset to 1e-2 at step 2 before the minimum (so the cap is 1e-2), floor 1e-13 |
The iteration counter is incremented also for the redo, so the redo is treated as "iteration 2" for the cap rule and the rotation flag of the solver (it is on only for the very first call, so the redo starts with the n x n dense solve). The empty-band threshold is `max(5 ethr, 1e-5)`. With `conv_thr` 1e-8 Ry (the run) `ethr` ends at about `0.1 x 1e-8/256 = 4e-12` Ry, nowhere near the floor.
Number of iterations per call: the call stops when no band moved by more than its threshold between consecutive iterations, so it follows from the interplay of (a) how loose `ethr` is relative to the change of the Hamiltonian since the previous SCF step, and (b) the preconditioner quality. At 1e-2 Ry through ethr about 1e-4 Ry in the first steps the starting vectors are already within the threshold for most bands after one correction block (1 to 3 iterations, as observed for the first four SCF steps); as `ethr` falls by orders of magnitude (to 1e-9 Ry and below at the end) more bands move above the threshold at the first test and 4 to 6 iterations are needed (58 total over 13 calls leaves 45 later iterations for the last 9 calls, if the first four calls take the observed 1 to 3: average 4 to 6 in the tail, consistent). The count of active bands in the later iterations is small (about 24) because after the first block the Ritz values of most of the 132 bands settle to better than `ethr` and only the slowest (typically the highest occupied ones, with the smallest gap to unoccupied states, and any band near a crossing with the empty ones) keep moving.

## 6. BAANDI in comparison, and points that could explain 99 ms versus 69 ms per iteration
What BAANDI does (from `crates/dft-solvers/src/lean_davidson.rs` header and `crates/dft-engine/src/convergence.rs`):
| Item | QE 7.6 regterg (si64 run) | BAANDI lean Davidson / standard profile |
|---|---|---|
| Convergence test | Ritz-value change between consecutive iterations; occupied `ethr`, empty `max(5 ethr, 1e-5)` Ry, flags recomputed every iteration | Ritz-value change flags, recomputed every iteration (same idea); strict bands = occupied plus the first empty band, higher buffers `max(tol, 5e-6)` Ha (equivalent to QE's 1e-5 Ry); an additional residual-energy guard can delay a stop |
| Threshold rule | `min(prev, 0.1 dr2/max(1, nelec))`, cap 1e-2 Ry, floor 1e-13 Ry | `min(prev, 0.1 error/max(1, Ne))` clamped to [5e-14, 5e-3] Ha; the same numbers in Ha; error is the Coulomb residual energy in Ha; plus a stall guard that tightens by 10 after five intervals without a factor-two reduction |
| First-step redo | yes (call 13) | yes ("standard redo") |
| Start of a call | always applies H to all n start vectors | a kept start (previous Ritz vectors and their H products) can skip the init block (REUSE-PSI); otherwise one H block of n |
| Capacity | 2n, with restart after iteration 1 in every multi-iteration call | 6 bands per basis (default `davidson_capacity_per_band`), contraction rarely needed |
| Reduced problem | bordered H and S, generalized `DSYGVX` of order nbase+u, one rank (root) then broadcast | S kept through a bordered Cholesky inverse T, standard solve of `A = T H T^T` per iteration (dsyevd / faer / secular update) |
| Corrections | u roots, residual by two GEMMs from stored products, diagonal preconditioner | same idea ("B1"); pivot test with orthonormalisation fallback |
| Stages | single level | coarse cutoff stage (1753 columns) before the fine stage (3504), then verification (768) |
Hypotheses for the cost per iteration (each with the number needed to test it; none is established):
1. H-block cost per column. QE's 4.5e3 columns through 8 ranks give about 0.9 ms all-in per column, and the FFT alone (one 72^3 transform per column, about 3.4e7 flops, of the order of 5 ms on one core per transform, 0.6 ms per transform on 8 ranks) already accounts for most of it. If BAANDI's fine stage costs 1.6 ms per column all-in, the gap is 0.7 ms per column or about 2.5 s over 3504 columns. Numbers needed: BAANDI's phase table per fine iteration (H time per column, in particular the transform and transpose time per pair and the projector GEMM) against QE's `h_psi`/`fftw`/`vloc_psi`/`h_psi:calbec` clocks for the same run.
2. The reduced eigenproblem and factor extension. QE solves a small DSYGVX (order 130 to 264) on one rank in a few ms; BAANDI does a bordered Cholesky extension plus a transformed eigensolve every iteration with possible replicated work on all ranks. If BAANDI's per-iteration reduced-problem time exceeds about 10 ms this is a main part of the 30 ms gap. Number needed: BAANDI `eigen` stage time per iteration at nbase about 130 to 190.
3. Block shape. QE's iterations are narrow (u about 24 of 132) except the first, which is one large iteration followed by a restart. BAANDI's capacity 6n lets the basis grow instead of restarting; if the basis exceeds 3n and u stays small, the border GEMMs of shape (nbase x u) and the two correction GEMMs of shape (2N x nbase x u) cost more per iteration than QE's after-restart nbase of 132 to 190. Number needed: BAANDI nbase trace per iteration in the fine stage and the mean u.
4. Per-iteration fixed costs spread over fewer, narrower blocks. BAANDI counts a fine-stage iteration as everything inside the fine stage divided by 58; if the fine stage includes mixing, potential, density and energy phases (not only the eigensolver), 99 ms is not comparable with 69 ms for the c_bands part alone. Number needed: both numbers as eigensolver-only wall per iteration, and QE's `c_bands`, `sum_band`, `v_of_rho`, `mix_rho` clocks.
5. Collectives. QE's solve has per iteration about three allreduces (border H and S, norms) over 8 ranks plus the broadcast of the eigenvector matrix from the root: the eigenvector matrix is nvecx x nvecx doubles = 264 x 264 x 8 = 558 kB per iteration. A BAANDI MPI implementation that reduces more matrices, or reduces full-size buffers instead of the bordered block, pays more. Number needed: BAANDI bytes reduced per iteration and number of collectives per iteration.
6. The fixed 2n floor per call is a QE cost, not a BAANDI one; by itself it favours BAANDI (kept starts skip 132 columns per call). ## Addendum (2026-11-23): the diagonal preconditioner (needed by the reference inner solver)
Read in the QE 7.6 routines g_psi, the diagonal set-up inside the band-diagonalization driver (c_bands) and usnldiag; written in our own words, no code.
- QE preconditions each correction vector component-wise in reciprocal space with a band-dependent denominator. For plane wave G and band k with current Ritz value e_k, let h(G) be the diagonal of the Hamiltonian and s(G) the diagonal of the overlap, and x = h(G) - e_k s(G), all in Rydberg. The correction coefficient is divided by d = (1 + x + sqrt(1 + (x - 1)^2)) / 2. This d is a smooth positive function: it tends to x for large positive x (kinetic-dominated high G) and to a value near 1 (one Rydberg) as x goes to zero or negative, so there is no division by a small number. The default build uses this smooth form; an older alternative (divide by x clipped away from zero with a floor of 1e-4) exists behind a compile switch and is not the default.
- The diagonal h(G) is the kinetic energy |k + G|^2 (Ry, Gamma: |G|^2) plus a constant local term v0, plus the diagonal of the nonlocal operator: for each atom, the sum over its projector pairs (i, j) of D_ij times beta_i(G) conj(beta_j(G)) (real part in the Gamma real path), where D is the (screened, for norm-conserving simply the bare) nonlocal coupling matrix of that atom in Ry. The overlap diagonal s(G) is 1 plus the analogous sum with the augmentation charges q_ij, which vanish for norm-conserving potentials, so s(G) = 1 here.
- v0 is the G = 0 component of the local potential as set when the local potential is assembled (INFERRED: the average of the total local potential used in h_psi at that moment; it is a constant shift, so it only moves x uniformly).
- The constant "1" inside d is one Rydberg: an implementation that works in Hartree must form x in Rydberg (twice the Hartree value) or rewrite d with the constant 1/2 Ha, otherwise the preconditioner changes. Real-Gamma pairing does not change the formula (it acts on each real coefficient).
