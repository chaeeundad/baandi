# B6: certificate H apply from cached projector products (design and physics half, 2026-11-10)

Status (updated 2026-11-10): physics-side API and the solver half are implemented behind `BAANDI_B6=on` (`ResearchOptions::b6`; default off, bit-identical when off). Solver hooks follow steps 1 to 5 below (trait defaults in dft-solvers lib.rs, cache `B6Cache` in real_davidson.rs, forwarding in dft-engine gamma_real.rs). Test `crates/dft-solvers/tests/b6_certificate.rs` (eigenpairs and counts bit-identical, every certificate takes the cached path across contracted restarts, thread-count independent, residuals within 1e-13). dev08 measurement: requests/micro-stack.md.

## Idea
At return, the real Davidson solver certifies by applying H to all Ritz vectors X = V C (V the orthonormal basis, C the Ritz coefficients) and recomputing the residuals. The nonlocal part of that apply is P D P^T X. Its first product P^T X costs 2 * count * n * bands flops. The solver already applied H to every basis column, so P^T V was computed once per basis column; P^T X = (P^T V) C costs 2 * count * m * bands with m the basis width (m much smaller than n). Only that product is skipped; local, kinetic, the coupling D and the back product P W are applied as before, so the certificate stays an explicit residual.

## Exactness class
Rounding class, not bit-identical: (P^T V) C and P^T (V C) sum in different orders. Unit test `cached_projections_reproduce_apply` (crates/dft-physics/tests/real_gamma_hamiltonian.rs, skewed two-species cell, s/p/d/f projectors, 104 projector columns): H X relative difference 1.1e-16; supplying the direct projections reproduces `apply_block` bit for bit. A certificate built this way can differ in the last digits of the residual; a residual right at the threshold could flip, so an A/B must report certificate verdict changes.

## Physics-side API (implemented, crates/dft-physics/src/real_gamma.rs)
- `RealNonlocal::projector_count()`, `RealNonlocal::last_projections(m) -> &[f64]` (P^T X of the latest application, column-major, `projector_count()` rows), `RealNonlocal::add_block_with_projections(projections, y)`.
- `RealHamiltonian::projector_count()`, `last_projections(m)`, `apply_block_with_projections(x, projections, y)` (local + kinetic + nonlocal from supplied projections).
- The default `add_block` / `apply_block` path is unchanged in arithmetic (the coupling and back product moved into a private helper, same operations in the same order).

## Solver-side call (to implement in real_davidson.rs by its owner)
1. Operator interface: extend `RealLinearOperator` with default methods `projection_count() -> usize` (0 = no support), `last_projections(m) -> Option<&[f64]>`, and `apply_block_with_projections(x, p, y)` defaulting to `apply_block`. The engine bridge in `crates/dft-engine/src/gamma_real.rs` forwards them to `RealHamiltonian`.
2. Cache: a `count x capacity` matrix Pv aligned with the basis columns. After every `apply_into(op, new_columns, ...)` that produces `products` for new basis columns, copy `op.last_projections(k)` into the matching Pv columns.
3. Every basis rewrite applies the same transform to Pv: restart and contraction (V <- V Q, so Pv <- Pv Q, `count x m x m'` flops), and any re-orthonormalisation that changes stored basis columns after their H apply (if such a path exists, it must either transform Pv or invalidate the cache; an invalid cache falls back to the plain apply).
4. Certificate: `pc = Pv[:, :m] * C[:, :bands]` (fixed-order GEMM), then `op.apply_block_with_projections(vectors, pc, actual)` in place of `apply_into(op, vectors, ...)`; count the H vectors exactly as before.
5. Switch `BAANDI_B6=on`, default off; off path untouched.

## Expected size (do not oversell)
Per solve the saving is one product of 2 * count * (n - m) * bands flops at the return certificate. si32 (Si vbc, about 128 projector columns, n about 11877 real rows, about 70 columns): about 0.2 GFLOP per certificate, a few tens of ms per solve, roughly 0.3 to 0.6 percent of a 40 s strict run with about 15 solves (E, not measured). It grows only if certificates become frequent or full-width (Track A, where every apply is full width and the same caching applies to every step, not just the certificate). Recommendation: implement the solver half together with Track A stage 1, not alone.

## Acceptance when implemented (proposal)
Same-binary env A/B on si16/si32 strict, T=1 and T=8, fresh seeds: energies within 1e-12 Ha, certificate verdicts and SCF counts unchanged (any change reported), nonlocal `other` GEMM flops reduced by the predicted amount, wall not worse than +1 percent on any cell.
